# Fresh AI semantic review

18개 패킷을 제공 원문·질문·문맥·고정 요구사항에 대조하여 수동 판정했다. 조건 키나 다른 평가 결과를 보지 않았으며 조건별 비교·집계는 하지 않았다. 모든 응답은 EXPLANATION이어서 전달 실패에 대한 NOT_ASSESSABLE 처리는 필요하지 않았다.

평가 표면은 explanation_ko이고 메타는 별도 감사했다. Annex C에 실제 있는 can 설명만으로 should 권고를 보존했다고 보지 않았지만 can 자체를 미지원 주장으로도 보지 않았다. 삭제 시점의 이름을 일반적인 특정 상태/각각의 삭제 시점으로 대체하면 복합 요구사항에서 누락으로 판단했다. 반면 동일하게/각각이라는 문장 내 연결이 저장 처리와 구체적 삭제 계기를 지시하면 준용을 인정했다.

명시적 권고와 금지형 재진술이 섞인 경우, 능력 보유와 능력 부여 구성의 허가가 섞인 경우, should/can 병기의 강도가 미해결인 경우에는 후보 해석을 rationale에 남기고 null을 사용했다. 대상의 should not을 권고 표현 없이 금지형으로만 반복하면 강도 변경으로 판정했다. 망이 운용 검증을 하도록 설정된 경우라는 전제는 단순 위치 검증 언급만으로 충족했다고 간주하지 않았다.

인용 진단은 citation_spec/version/clause의 source 필드 정확 일치 여부이다. 본문에 문헌 식별자가 모두 적혀 있는지를 의미하지 않는다. source에 맞는 추가 메타 내용은 그 자체로 본문과 모순이라고 보지 않는다. 다만 대상 규범 라벨과 설명 규범 강도의 충돌, 또는 조건/예외 역전은 별도 감사에 반영했다.

인용은 문맥을 보존하도록 온전한 실제 응답 문장과 제공 원문 블록을 사용했다. 문장 수는 18개 모두 세 문장으로 수동 확인했으며 코드의 문장 분리는 인용 추출을 위한 것뿐이다. 코드에 수동 값과 사유를 먼저 작성한 뒤 전체 완수 결합만 결정적으로 수행했다.

세 허용 입력만 읽었다. 일반 시스템/사용자 지침과 부모의 제한된 과업 안내는 알고 있었으나 생성 프롬프트, 조건 배정, 과거 판정, 부모 판정은 전달받거나 읽지 않았다. 파일 외 기억 조회·웹/API·다른 에이전트 요청은 하지 않았다. 두 AI 평가는 사람 전문가 검증 또는 독립 생성 표본이 아니다.
