# 봉인 이후 진단 범위 설명

이 문서는 부모의 방법론 확인 요청에 대한 사후 설명이다. 원래 세 봉인 파일을 변경하지 않았고 대체 판정이나 의미 점수 재평가를 발행하지 않는다. 다른 평가자의 판정 및 조건 키는 읽지 않았다.

고정 metadata_inconsistency를 JSON_EXPLANATION_INCONSISTENCY, 즉 메타데이터와 explanation_ko 사이의 모순으로 해석하면, 원래 fresh 검토 일부 사유는 그 진단과 메타데이터의 원문 적합성을 혼용했다. 원문과 다른 메타데이터라는 사실만으로 설명과도 모순된다는 결론은 나오지 않는다. 특히 설명과 메타데이터가 같은 오해를 공유할 수도 있다. 따라서 아래 원래 값들은 순수한 교차 필드 모순 발생률의 자료로 그대로 해석할 수 없다.

| ID | 봉인 사유가 실제로 비교한 대상과 이 설명의 범위 |
|---|---|
| GPR-002 | obligation 및 의무적 저장 action을 원문 should 권고와 비교했다. 설명도 저장해야 한다고 서술하므로 봉인 사유는 메타-설명 모순을 입증하지 않는다. 긴급 삭제 계기가 메타에도 없다는 누락 역시 두 필드 사이 모순의 근거가 아니다. |
| GPR-013 | capability 라벨과 원문 recommendation을 비교했다. 설명의 can 가능성과 라벨 사이 직접 모순을 그 사유에서 따로 입증하지 않았다. |
| GPR-016 | permission 라벨과 원문 recommendation을 비교했다. 설명도 저장할 수 있다고 표현하므로 그 비교만으로 메타-설명 모순을 입증하지 않았다. |
| GPR-004 | permission과 원문의 선택적 capability 보유를 비교했다. 설명에 구성 허용 해석이 있어 원문 부적합성과 교차 필드 모순을 동일시할 수 없다. |
| GPR-010 | permission과 원문의 capability 보유를 비교했다. 봉인 설명 판정 자체는 능력 부여 구성의 허용이라는 표현을 미해결로 남겼다. 라벨의 원문 불일치만으로 설명과의 모순이 확정되지는 않는다. |
| GPR-008 | condition/exception 구조를 대상 비거절 권고와 비교했다. 교차 필드 명제 대조를 별도로 제시하지 않았으므로 사유에 같은 진단 범위 혼용이 있다. |
| GPR-012 | condition/exception이 원문의 unless와 역전된다는 비교이다. 원문 구조 감사이며, 설명 자체의 해석도 미해결이어서 이 사유만으로 교차 필드 모순을 확정할 수 없다. |
| GPR-015 | 충분한 정보가 있는 경우라는 condition을 대상 비거절 권고의 적용 조건과 비교했다. 명시적인 메타-설명 대조 대신 원문 적합성을 판단한 사유이다. |

직접 질문된 GPR-002, GPR-013, GPR-016은 원문 불일치를 측정한 사유가 맞다. 같은 구분의 영향을 받는 다른 봉인 true 사유는 GPR-004, GPR-010, GPR-008, GPR-012, GPR-015이다. 이 열거는 사유의 진단 대상을 식별한 것이며 해당 값에 대한 새 true/false/null 판정을 부여한 것이 아니다.

GPR-007 및 GPR-018의 사유는 메타의 discouragement와 설명의 금지형 강도를 명시적으로 대조했으므로 위 원문 비교만의 사유들과 구분된다. GPR-003, GPR-006, GPR-014의 null 사유 역시 메타와 설명 사이 해석 관계의 미해결을 언급했다. 다른 false 사유에서도 원문 일치 여부를 참고했지만, 이 부록은 그것들을 재판정하지 않는다.

원본 의미 완수, 요구사항 coverage, 미지원·왜곡 판정에는 어떤 변경도 없다. 향후 교차 필드 진단을 다시 평가할 필요가 있다면 별도 허가된 버전 및 근거가 필요하며, 이 부록 자체는 독립 새 검토나 조정 판정이 아니다.
