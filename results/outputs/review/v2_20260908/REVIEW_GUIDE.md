# v2 의미 검토 안내

상태는 `PREPARED_PREFLIGHT_PENDING`이다. 이 파일은 검토 방법을 안내하며 어떤 응답의 성공·실패도 미리 정하지 않는다. 먼저 51개 기준의 source/gold 사전 확인을 마치고, 그 결과를 고정한 뒤 255개 설명을 검토한다. 현재 모든 판정 칸은 비어 있다.

## 읽는 순서

1. `preflight/references.jsonl` 또는 `preflight/readable/`의 원문·질문·정답 참고 필드를 확인한다. `preflight/judgments_blank.jsonl`을 별도 작업 폴더에 복사해 51개 기록을 작성한다. CSV는 같은 내용의 열람·편집 보조본이고 검증 도구의 입력은 JSONL이다.
2. 사전 확인에서 원문 명제, 규범 적용 범위, 조건·필요조건·양화·예외·참조의 관계를 기록한다. 정답 필드는 확정 진리가 아니다. 동결된 정정은 이미 참고 필드에 반영되어 있다. 새 충돌은 `UNRESOLVED`와 errata 제안으로 남기며 참고 필드를 직접 덮어쓰지 않는다.
3. 사전 확인 완료 후 `reviewer/pass1/readable/` 또는 `packets.jsonl`을 정해진 순서로 읽고 `judgments_blank.jsonl`의 별도 사본을 작성한다. 앞선 결과나 조건 매핑을 열지 않는다. 하나의 응답에서 여러 문장을 함께 읽어 최종 의미를 판단한다.
4. 1차 전체 기록을 검증하고 봉인한 뒤 최소 24시간 후 별도 순서의 2차 자료를 만든다. 2차 검토에는 1차 점수·메모를 제공하지 않는다. 두 검토를 마친 뒤 불일치를 조정한다.

`coordinator/`는 조건·원본 ID·입력 경로·집계 매핑이 있으므로 가림 검토 자료에 포함하지 않는다. 같은 평가자의 사전 지식과 응답 문체로 인한 추론 가능성은 남아 있다. 독립 전문가 검증이나 완전한 눈가림이라고 표현하지 않는다. 시간 검사와 파일 분리는 절차 검증이며 접근 통제나 위변조 방지 장치는 아니다.

## 의미 판단 기준

- 규범 표현이 무엇에 걸리는지 보존한다. ‘X 능력을 선택적으로 보유할 수 있음’을 단순한 X 행동 허가나 보편적인 능력 보유로 바꾸지 않는다.
- 실제 선행 행동이 필요한 문장은 능력 보유만으로 대체하지 않는다. 필요조건을 충분조건으로 바꾸지 않는다.
- 설명 전체를 읽는다. 뒤 문장이 누락을 명확히 보완하는 경우와 앞뒤 명제가 실질적으로 충돌하는 경우를 구별한다.
- 주체·행동·대상·조건·규범 강도·부정·양화와 명제 사이의 관계를 확인한다. 유형 이름이 맞는 것만으로 성공 처리하지 않는다.
- 참조 안내를 행동의 예외로 만들지 않는다. 제공된 source/question과 판정자 전용 PDF 문맥을 구별한다. 입력에 없던 PDF 문맥을 모델이 받았다고 소급하지 않는다.
- 영어 전문 용어 유지와 의미가 같은 한국어 표현은 모두 허용한다. 문체·어순만으로 감점하지 않는다.
- 골드의 대응 관계나 문맥이 미확정이면 근거 없이 단일 해석을 강제하지 않는다. 별도로 명백한 오류가 있다면 그 오류에 근거한 실패는 가능하며 `INDEPENDENT_CLEAR_ERROR`를 기록한다.

상세 기준은 작업 관리자가 고정한 rubric SHA-256으로 연결된다. 이 안내와 동결 기준에 충돌이 있으면 동결 기준을 우선하고 충돌 사실을 기록한다.

## 기록 방법

사전 확인의 `gold_status`는 `SOURCE_SUPPORTED` 또는 `UNRESOLVED`, `input_context_gap`은 `NONE_IDENTIFIED`, `IDENTIFIED`, `UNRESOLVED` 중 하나다. 전자는 source 기준의 타당성이고 응답의 정답 여부가 아니다. `propositions_and_relations`에는 다음 구조의 객체를 한 명제마다 작성한다. 빈 문자열 또는 빈 배열을 자동 성공으로 채우지 않는다.

```json
{"actor":"원문의 주체", "modal_surface":"원문의 규범 표현", "modal_scope":"직접 적용되는 구절", "action_or_state":"행동 또는 상태", "condition":"조건 또는 없음", "quantifier":"한정 또는 없음", "relation":"다른 명제와의 관계", "evidence_quote":"근거 원문 인용"}
```

`source_provenance`는 근거 인용, 규격·버전·조항·PDF 페이지, `evidence_location`(`reference_source`, `reference_question`, `adjudication_only_context`)를 담은 객체 배열로 기록한다. reference는 평가용 자료를 뜻하며 모델이 그 자료를 받았다는 뜻이 아니다. 실제 extractor/generator 입력 제공 여부는 가림 검토 후 관리자가 원본 입력·조건 매핑으로 연결한다. 질문의 전제도 원문과 일치하는지 확인한다. 근거 위치가 다르면 명제를 나누어 기록한다.

설명이 있으면 `semantic_judgment`는 `PASS`/`FAIL`/`UNRESOLVED`이며 `complete_preservation`은 각각 `1`/`0`/`null`이다. 생성 보류·거절·빈 응답·파싱 실패는 의미 판정을 `NOT_SCORED`, pipeline 결과를 `0`으로 기록한다. 원본 레코드 자체의 누락·변조는 검증 실패이며 생성 보류로 바꾸지 않는다. 준비 단계의 빈 칸과 `null`은 미판정 자리 표시일 뿐 확정 결과가 아니다.

모든 기록에 평가자, 시간대가 있는 실제 검토 시각, 판정 근거, 원문 근거를 남긴다. 1차 검토 시각은 전체 source/gold 사전 확인 완료 이후여야 한다. 평가 시각을 예상 날짜나 파일 생성 시각으로 대신하지 않는다. 이전 점수 복사나 특정 실패 응답만 재판정하지 않는다.
