# 별도 AI 문맥의 의미 범위 검토

검토자는 별도 Codex AI 문맥의 reviewer_a이다. 사람 도메인 전문가 검증이 아니며, 같은 모델 계열의 새 문맥은 오류 독립성이나 통계적 독립을 보장하지 않는다. 동결 v2와 허용된 15개 packet/빈 양식/검토 안내, 지정된 원문 페이지의 TXT 및 필요한 PNG만 의미 검토에 사용했다. PDF 두 파일은 제공된 원본 해시 확인 목적으로만 읽었고 PDF 본문을 새로 추출하지 않았다. 과거 판정, 조건 키, 상위 보고서, 메모리, 다른 작업의 기록은 열지 않았다. 안내 자체의 후속 검토 설명은 검토 자료의 일부이며 완전한 실험적 눈가림을 주장하지 않는다.

판정 단위는 설명 전체의 명제와 연결 관계다. JSON 유형, 추출 힌트 또는 과거 점수로 설명을 보충하지 않았다. 추가 문맥은 원래 생성자에게 제공되지 않았고, 짧은 원문 제공 여부는 각 packet의 값으로 따로 기록했다. 세 인용 문장은 확인한 페이지에서 NOTE 내부가 아닌 본문에 위치한다. 원래 선정 규약 전체나 gold 파일은 허용 자료에 없으므로 표본 적격성 및 gold 전체 타당성을 새로 인증하지 않는다.

## G010 — 선택적인 능력 보유

TS 23.501 v18.12.0, 4.2.3, PDF 45쪽의 원문은 “However, each SMF may also have the capability to control both a local and a central UPF within a PDU Session.”이다. 바로 앞에는 두 PDU Session에 두 SMF를 선택하는 구성이 있으며, 해당 문장은 하나의 SMF가 한 PDU Session 안에서 두 종류 UPF를 제어하는 능력을 보유할 수도 있다는 추가 가능성을 둔다. may의 직접 범위는 능력의 보유다. 제어 행동의 허용으로 옮기는 설명이나 각 SMF의 가능/능력 보유를 단정하는 설명은 그 선택성을 자동 보존하지 않는다.

R1은 이 구별을 직접 정한다. “능력이 있을 수 있다”는 보유 여부를 열어 두고 제어 대상을 명시한다. “이는 … 기술적 가능성”이라는 부연은 앞의 중첩 표현을 삭제하지 않으므로 전체 설명으로 판단한다. 반대로 “제어하도록 허용된다”와 “기술적 가능성이 있다”만 남은 응답에는 보유 선택성을 복원하는 문장이 없다. 각 행의 실제 표현과 지원되지 않는 추가 주장까지 개별 근거에 남겼다.

FOLLOWUP-003의 “능력이 있다. 이는 허용 또는 선택 가능”은 ‘이는’이 능력 보유 전체를 받는지 제어 행동을 받는지 분명하지 않다. R3은 바로 이 지시 대상의 불확실성을 유보하도록 한다. 동결 규칙은 유보 상태를 정하기에는 충분하지만 이 문장의 0/1을 확정하기에는 충분하지 않다. 단순히 뒤에 ‘선택’이 있다는 이유로 성공 처리하거나 앞 문장만 떼어 실패 처리하지 않았다. 별도 규칙을 만들어 해결하지 않았다.

## G023 — Annex C 참조의 보존과 전개 수준

TS 24.501 v18.12.0, 4.6.2.2, PDF 98쪽의 원문은 “The allowed NSSAI(s) should be stored in a non-volatile memory in the ME as specified in annex C.”이다. 저장 대상, 위치, 권고 강도와 Annex C에 따르는 관계가 직접 명제다. Annex C는 규범 부속서이며 확인한 PDF 1089~1093쪽은 단순한 문헌 안내 이상이다. C.1은 SUPI와 함께 저장하는 권고(PDF 1090쪽), SUPI 일치에 따른 사용 조건 및 불일치 시 삭제(PDF 1091쪽), 응급 서비스 등록/eCall only의 비휘발성 저장 금지(PDF 1091쪽)를 담는다. C.2는 SNPN 모드의 저장 및 식별자 조건을 나눈다(PDF 1091~1093쪽). 그 전부나 모든 상호 참조를 다 조사한 것은 아니다.

‘부속서/부록 C에 명시된 방식에 따라’ 또는 ‘명시된 바와 같이’는 원문 준거 관계를 유지한다. 능동/수동 전환과 NSSAI의 한국어 수 표현은 대상 관계를 바꾸지 않는 한 실패 이유가 아니다. 그러나 R7은 참조 대상에 실제 규범 조건이 있으면 출처와 입력 제공 여부를 구분하라고 할 뿐, 참조를 유지한 짧은 설명에서 그 조건을 몇 단계까지 명시적으로 전개해야 complete_preservation인지 정하지 않는다. 이 범위 차이만으로 판정이 갈리는 FOLLOWUP-004/005/006/008은 유보했다. 이는 문장이 분명한 오역이라는 결론이 아니다.

FOLLOWUP-011은 범위 정책과 별도로 ‘should’를 ‘저장해야 하며’로 강화하는 직접 오류가 있다. 뒤의 ‘일반적으로’는 PLMN별 보관 설명에 걸려 저장 의무 자체를 수정하지 않는다. 이 독립적인 오류에는 새 참조 전개 규칙이 필요하지 않다. 원문 미제공을 파이프라인 실패나 빈 응답으로 바꾸지 않았다.

새 기준을 제안한다면 직접 문장/참조 관계의 보존과 참조 대상 내용의 설명을 구분하고, 필요한 전개 수준을 후속 버전에서 미리 고정해야 한다. 이번 판정에 새 기준을 적용하지 않았다.

## G028 — NR 위성 접속 문맥과 직접 비권고 명제

TS 23.501 v18.12.0, 5.4.11.4, PDF 133쪽의 직접 명제는 충분히 정확한 위치정보로 UE가 PLMN 운용 불가 지역에 있음을 판단할 수 있는 경우를 제외하고 AMF가 요청 거절/등록 해제를 하지 않는 것이 권고된다는 내용이다. 비권고의 예외는 자동으로 거절 의무 또는 거절 허용 전체를 뜻하지 않는다.

PDF 132~134쪽을 보면 5.4.11은 NR 위성 접속을 다루고, 5.4.11.1은 “This clause describes the specific aspects for NR satellite access.”라고 범위를 밝힌다. 해당 문단도 NR 위성 접속 UE의 위치 검증을 전제로 한다. 이 범위는 짧은 원문과 질문에 없던 판정자 전용 문맥이며 원래 생성 입력에 소급하지 않았다. 관련 없는 WUS, 망 선택, TAI 처리와 NOTE 전체를 추가 필수 명제로 삼지 않았다.

FOLLOWUP-002/007/010은 설명 전체에 직접 문장의 비권고와 위치정보 예외 관계를 유지한다. ‘그 정도로’는 앞 문장의 지역 판정에 필요한 정확성에 연결되고, ‘다만’은 앞의 비권고를 후문에서 한정한다. 첫 문장만 떼어 일반화 오류로 삼지 않았다. 세 응답은 NR 위성 접속을 명시하지 않지만 모든 접속 방식/모든 거절 사유에 적용한다고 명시적으로 주장하지도 않는다. 동결 출처 규칙은 추가 문맥을 구별하게 하지만 생성 입력에 없는 상위 범위의 단순 생략을 어떤 분모의 완전 보존으로 처리할지는 정하지 않는다. 그러므로 그 차이만 남은 세 행은 유보했다.

FOLLOWUP-012의 ‘해서는 안 된다’와 ‘때에만 … 가능하다’는 비권고를 강제 금지로 높이며 후문도 이를 바로잡지 않는다. FOLLOWUP-014는 거절/등록 해제에 연결된 비권고를 누락하고 위치정보 확인만 요구한다. 이 두 행의 독립적인 오류는 상위 범위 생략 정책을 새로 정하지 않아도 판정할 수 있다.

후속 버전에서 생성 입력에 없는 상위 범위를 생략한 경우와 그 범위를 넘어선 적용을 명시적으로 주장한 경우를 구분하는 기준을 고정할 것을 제안한다. 이번 검토는 유보를 0이나 1로 바꾸지 않았다.

## 기록과 시간의 의미

15행의 reviewed_at은 개별 수동 판정문 작성 후 파일에 확정 기록한 실제 UTC 시각이다. 행별 읽기 시간을 따로 계측하지 않았으며 행별 검토 소요 시간으로 해석하지 않는다. 최초 자료 로딩 직후 확보한 시각부터 최종 인용·구조 검증까지의 실제 구간은 manifest에 기록했다. 이 구간은 사람 검토 시간이나 모델 추론시간 계측값이 아니다. 직렬화 코드에는 점수를 추론하는 규칙이나 기본 채점값이 없으며, 15개 판정과 점수는 모두 개별 작성했다. 검증 코드는 인용 일치, 필드 보존, 고유 ID, 점수-상태 유형과 해시만 확인했다.
