# C1M 규범 유형 힌트 확장 규약

2026-09-06. C3 첫 의미 평가를 본 뒤 설계한 후속 탐색 실험이다. 동일 main 72건에서 C1 원문 프롬프트에 정답 normative_type과 polarity만 추가한다. 정답 actor·condition·action·exception과 gold_summary, 난도, 기존 응답·점수는 입력하지 않는다. 공개된 원문 자체에 같은 단어가 포함되는 것은 금지 대상이 아니다.

## 질문과 우선순위

C1 대비 정답 규범 힌트 C1M의 차이가 얼마나 큰가? C2의 이득이 규범 유형의 정답 힌트로도 나타나는지 살펴본다. C1M은 oracle ablation으로 자동 추출의 타당도나 새로운 표본 일반화를 검증하지 않는다. C2와 C1M은 원래 지시문도 일부 다르므로 그 차이를 나머지 네 구조 필드만의 순수 인과 효과로 주장하지 않는다.

우선순위는 (1) 논문에 첫 의미 평가 및 불확실성 반영, (2) 조항 단위 통계 보강, (3) C1M 72건 실행, (4) 지연 의미 재검토·불일치 조정, (5) 추출기 v2와 새 조항 검증이다. 기존 72건에서 본 실패를 고친 뒤 같은 표본의 성능을 독립 검증으로 보고하지 않는다. 모델 확대나 실제 검색 통합은 뒤로 둔다.

## 고정 설계

- 데이터: 동결 main 72건 전체, modal별 12건. 기존 C0/C1/C2/C3 응답은 재생성하지 않는다.
- C1의 기존 문구를 그대로 유지하고 출처 블록 앞에 normative_type/polarity 두 줄의 정답 힌트 블록만 삽입한다. 블록을 제거하면 원래 C1 프롬프트와 byte 단위로 같아야 한다.
- 모델 gpt-5.4-mini-2026-03-17, temperature 0, reasoning effort none, 최대 출력 600 tokens, 기존 response schema, store false.
- 최대 성공 호출 72회. 순서는 seed `c1m-main72-v1-20260906`의 hash 순이며 생성 seed가 아니다.
- 기존 키 재사용은 이 작업에서 이미 승인됐다. 추가 실행 추정 비용 상한은 $0.50이다. 매 요청 전 보수적 입력 byte·출력 상한으로 비용을 예약하고 usage 기반 추정 비용을 누적한다. 실제 청구액 보장은 아니다.
- 429/5xx만 최대 두 번 재시도한다. 전송 결과 불명확, 인증·quota·모델 불일치 시 중단한다. 의미 오류·파싱 실패를 더 좋은 답으로 바꾸기 위한 재실행은 하지 않는다. 기존 run이 있으면 execute를 거부한다.
- 실행 전에 데이터·프롬프트·구현·schema·순서 및 projected input hash를 고정하고 모든 요청/응답, 실제 모델, usage, 경과 시간과 실패를 저장한다.

## 검증과 평가

요청 projection은 원문·질문·출처·정답 규범 유형과 polarity로 제한한다. 나머지 gold 필드와 case ID를 변조해도 API 입력이 같음을 72건 전수 검사한다. 반대로 modal/polarity 변경은 힌트 블록만 바꿔야 한다.

JSON normative_type·인용 ID 일치는 결정적 진단으로만 보고한다. 의미 채점은 새 원문 대조가 필요하며 미기재 판정은 성공이 아니다. 보류·빈 출력·파싱 실패를 전체 72개 분모에서 실패로 포함한다. C1/C2/C1M의 새 216행 masked 평가 자료를 준비하며, 조건 대응 키는 분리한다. Codex는 이전 결과를 알고 있어 독립 맹검·전문가 검증이라고 표현하지 않는다.

새 의미 평가 후 C1M−C1 완전 보존 차이, case paired bootstrap 20,000회, 양측 exact McNemar를 주 분석으로 사용한다. C2−C1M 및 원래 모호성 3건 제외는 보조 분석이다. 생성 시점과 평가 시점이 다르면 명시한다. 데이터·지표·프롬프트를 결과에 맞춰 교체하거나 유의해질 때까지 늘리지 않는다. 검토가 끝나기 전 논문에는 확정 의미 성능을 넣지 않는다.
