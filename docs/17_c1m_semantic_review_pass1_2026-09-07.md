# C1M 규범 유형 힌트의 첫 의미 평가

2026-09-07. 규범 유형·부정 정답만 C1에 추가한 C1M의 설명 완전 보존은 첫 Codex 평가에서 68/72(94.44%)였다. 원문 단독 C1 61/72보다 높지만 전체 72개에서 양측 exact McNemar p=0.06543이며, 아직 지연 재검토가 끝나지 않은 잠정 결과다. C2와의 비유의 차이를 동등성이나 같은 효과의 증거로 해석하지 않는다.

## 평가 방법과 상태

9월 6일 생성된 C1M 72개와 기존 C1/C2 각 72개를 섞은 M001–M216을 전수 대조했다. 각 행의 원문·gold·설명에 대해 6개 명시적 판단과 근거를 직접 기록했고, 9월 7일 14:56:15.827828 KST에 동결한 뒤 키를 복원했다. 빈 점수를 기본 성공으로 채우지 않았다. C1/C2 응답은 방금 C3 지연 비교에서도 검토했으므로 기억 효과가 크다. 해당 144행의 모든 세부 판정은 C3 지연 조정 결과와 같았다. 오늘의 432개 행 검토는 반복된 C1/C2를 포함하며 서로 다른 응답 432개나 독립 평가 432개가 아니다.

모든 평가 자료가 실제 원문 및 보존된 모델 응답과 일치하는지 확인했다. C1M 생성 입력·출력·모델·usage 무결성 검증도 다시 통과했다. 검증기의 `meaning_preservation: NOT_EVALUATED`는 생성 검증기 자체가 의미 점수를 부여하지 않는다는 범위다. 최신 의미 결과는 `review/summary_pass1.json`에 있다. 이번 평가에는 추가 API 호출·비용이 없고 기존 생성 비용은 약 $0.08409다.

C1M의 JSON normative_type은 72/72지만 설명에서 규범 강도·부정과 그 적용 범위의 공동 판정은 70/72다. 유형 이름만 맞추는 것으로 주체와 행위의 연결까지 보장되지 않는다. C1M에서 새로 실패하고 C1에서는 성공한 두 사례는 CAN-004와 MAY-011이다. 따라서 힌트가 모든 사례를 단조롭게 개선한 것도 아니다.

MAY-001(M057)은 능력이 있다고 서술한 뒤 허용·선택 가능이라고 한정했고, CAN-008(M111)은 첫 문장의 능력 표현 뒤에 실제 context 수립이 보안 활성화 전제임을 명시했다. 첫 평가에서는 설명 전체를 읽어 성공으로 판정했지만 scope 플래그를 남겼다. 이 두 성공을 보수적으로 실패로 바꾸는 별도 사후 stress test에서는 C1M 66/72, C1M−C1 +6.94%p, p=0.22656이다. 이는 통계적 신뢰구간이나 변경된 정식 점수가 아니라 두 해석 선택에 대한 민감도다.

정답 modal 힌트가 C2의 높은 점수 일부를 설명할 가능성을 보여 주지만, C2의 나머지 구조 필드 효과와 프롬프트 문구 효과를 순수하게 분리한 결과는 아니다. 동일 모델·설정에서도 생성일 차이와 단일 실행 변동이 남는다. 새 조항 일반화나 자동 추출의 성능도 이 실험으로 입증하지 않는다.

## 이어갈 작업

C1M 첫 평가 완료로부터 24시간이 지난 **2026-09-08 14:56:16 KST 이후** 새 순서로 지연 재검토한다. `delayed_pass2/`의 H001–H216 자료는 점수가 모두 비어 있는 준비 상태이며 예약이나 자동 실행을 설정한 것은 아니다. 지연 검토와 불일치 조정이 끝날 때까지 C1M은 잠정치로 유지한다.

평가 기준을 결과에 맞춰 바꾸지 않고, 추출기 v2에서는 (1) 규범 표현과 actor/action 원문 구절의 연결, (2) 실제 전제·조건 및 양화 보존, (3) 참조와 예외 구분을 개선 대상으로 삼는다. 기존 72개는 개선에 사용한 개발 표본이며 독립 검증에는 새 조항이 필요하다.
