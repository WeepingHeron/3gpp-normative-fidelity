# 규범 강도·명제 누락 방지 생성 실험 계획

2026-09-09 · 설계 검토 반영본 · **18개 요청과 실행·평가 규칙을 동결 대상으로 확정했다.** 실제 동결 시각과 해시는 [입력 동결 manifest](../experiments/generation_preservation_v1_20260909/input_freeze_manifest.json), 검토·처리 근거는 [설계 검토 기록](../outputs/review/generation_preservation_preflight_20260909/design_review.md)을 따른다. protocol의 `READY_TO_FREEZE`는 동결 직전 상태를 그대로 보관한 값이다. 이 기록 시점의 새 API 생성은 0회다.

이번 질문은 **충분한 원문 문맥을 동일하게 제공했을 때, 구체적인 규범 강도 보존 지시와 명제 누락 점검 지시를 추가하면 한국어 설명의 완수율이 높아지는가**다. 기존 개발 사례 3개로 방법의 동작을 먼저 확인하고, 정해 둔 진행 기준을 통과하면 새 조항에서 별도 평가를 준비한다.

## 출발 근거와 가설

[직전 24회 문맥 실험](30_separate_ai_review_and_context_microstudy_2026-09-09.md)에서는 문맥 제공 후 SUPI 조건과 NR 위성 접속 범위가 일부 더 보존됐지만 전체 과제 완수는 늘지 않았다. FULL 입력에도 있던 긴급 서비스 등록 해제 시 삭제 조건이 빠졌고, should/should not을 의무·금지로 강화하는 오류가 남았다. 따라서 다음 개입은 문맥량을 더 늘리는 대신 **같은 근거에서 설명을 작성하는 지시**를 바꾼다.

가설은 두 가지다. 명시적인 강도 보존 지시가 권고의 의무화를 줄일 수 있고, 여기에 명제 점검 지시를 추가하면 예외와 후속 행동의 누락도 줄일 수 있다. 모두 아직 검증하지 않은 가설이다. 기존 결과를 보고 설계한 개발 실험임을 밝히며 연구 전체의 사전 등록으로 표현하지 않는다.

## 비교 조건과 규모

| 조건 | 생성 입력 | 확인하려는 차이 |
|---|---|---|
| A0_BASE | 직전 FULL/NONE과 정확히 같은 요청을 새로 실행 | 현재 생성 방식의 동시 기준선 |
| A1_MODAL | A0 + 구체적인 규범 강도 보존 지시 | should/should not, unless, 능력 보유의 적용 대상 보존 |
| A2_MODAL_CHECK | A1 + 일반적인 명제 누락 점검 지시 | 조건·예외·후속 행동까지 설명에 남기는 추가 효과 |

**3개 원문 × 3조건 × 2회 반복 = 18회**, 조건당 6개 응답이다. 주 비교는 **A2−A0**, 보조 비교는 A1−A0와 A2−A1이다. 직전 응답을 새 기준선으로 재사용하지 않으며 새 18개 응답끼리 비교한다. A0에도 기본적인 규범 구분 안내가 이미 있다. 따라서 A1은 규범 안내의 유무가 아니라 **더 구체적인 지시를 추가한 효과**를 측정한다.

세 조건 모두 동일한 FULL 원문·질문·출처·JSON schema·2~4문장 제한·출력 상한을 사용한다. 사례별 정답 라벨, 평가 요구사항, 기존 판정이나 모범답안은 생성기에 주지 않는다. 검색, C3 추출기, 추가 모델 호출, 생성 후 수정은 포함하지 않는다. 사례와 반복 번호로 대응시키되 모델의 같은 난수 시드를 공유하는 대응 실험이라고 주장하지 않는다.

실제 추가 문구는 [강도 보존 지시](../experiments/generation_preservation_v1_20260909/modality_instruction.md)와 [누락 점검 지시](../experiments/generation_preservation_v1_20260909/checklist_instruction.md)에 저장했다. 모든 사례에 동일하게 적용한다. A2의 점검은 **출력 전 점검을 요청하는 프롬프트 개입**이다. 별도 점검표나 추론 과정을 받지 않으므로 모델이 내부에서 그 절차를 실제 수행했다고 검증할 수 없다. 추출기나 결정적 검증기를 구현한 것으로 표현하지 않는다.

추가 지시 때문에 입력 길이와 강조 횟수도 증가한다. 따라서 차이가 나더라도 특정 점검 내용만의 효과나 내부 추론 기제의 증거로 단정하지 않는다. 길이를 맞춘 중립 지시 대조군은 이번 3조건에 포함하지 않는다. FULL 문맥의 대상 문장 반복은 모든 조건에서 동일하다. 2~4문장 제한이 복합 예외를 담기 어렵게 할 수 있지만, 이번 비교에서는 그대로 유지하고 설명 길이·출력 token·잘림 여부를 함께 기록한다. 길이 제한 완화는 별도 후속 변수로 다룬다.

## 원문과 평가 범위

| 사례 | 동결 요구사항 | 개발 실험에서의 역할 |
|---|---|---|
| CTX-001 / G010 | 선택적인 능력 보유, 하나의 PDU Session에서 두 UPF 모두 제어 | 잘 보존되던 의미가 새 지시 때문에 악화되는지 확인 |
| CTX-002 / G023 | 비-SNPN 저장 권고, SUPI 결합·사용·삭제, 긴급 등록 예외, eCall 예외 | 강도와 복합 예외·삭제 조건을 함께 확인 |
| CTX-003 / G028 | 위치정보 unless와 비권고, NR 위성 접속 범위, 망의 위치 검증 설정 | 부정 권고의 강화와 적용 범위 누락을 확인 |

원문·문맥·질문·평가 요구사항은 직전 동결 자료에서 그대로 가져온다. CTX-002의 질문은 이미 직전 실험에서 비-SNPN 저장·사용·예외로 구체화된 것이며 과거 v2와 같은 과제가 아니다. 평가 항목은 2+4+3=9개다. 조건과 반복을 곱하면 **검토자 1명당 응답 18개·요구사항 판정 54개**다. 두 검토자의 기록을 생성 표본 36개로 세지 않는다.

[생성기용 자료](../experiments/generation_preservation_v1_20260909/generator_inputs.json)와 [평가자용 요구사항](../experiments/generation_preservation_v1_20260909/evaluation_reference.json)을 분리했다. 실제 요청 미리보기는 필요한 영문·질문·출처만 선택해 구성한다. 평가 필드를 임의의 표식으로 바꿔도 요청이 같아야 한다는 검증을 포함한다. 세 사례는 이미 결과를 보고 선택한 개발 사례이므로 미관찰 평가셋으로 부르지 않는다.

## 평가와 미확정 처리

**주 지표는 한국어 설명의 문맥 포함 과제 완수**다. `explanation_ko`만 읽고 모든 지정 요구사항을 정확히 보존했는지 평가한다. 각 항목은 충족 1, 누락·모순 0, 의미 미확정 null로 기록한다. 복합 예외는 나열된 조건과 후속 행동의 계기가 모두 보존돼야 1이다. 표현이 다르다는 이유만으로 틀렸다고 하지 않는다.

전체 완수는 어느 요구사항이든 0이거나 미지원·왜곡 주장이 확인되면 0, 명확한 실패 없이 미확정 항목이나 주장이 남으면 null, 나머지는 1이다. **미지원·왜곡 여부**를 별도 축으로 보고한다. 메타데이터 유형, 설명과 메타데이터의 모순, 출처 필드 오류는 별도 진단으로 남기며 올바른 JSON 라벨이 설명의 오류를 복구하지 않는다. 전체 완수는 출처 필드까지 포함한 서비스 전반의 성공률을 뜻하지 않는다.

두 AI 검토자는 각자 18개 전체를 평가한다. 익명 응답 ID, 원문·질문·요구사항과 응답을 제공하고 패킷에서는 조건명·생성 지시·기존 점수·다른 검토자의 판정을 제외한다. 진행 AI는 설계와 과거 결과를 이미 알고 있어 그 사전 지식까지 가렸다고 주장하지 않는다. 별도 AI는 해당 기록을 전달하지 않은 새 문맥에서 검토한다. 각 판정의 응답 인용·원문 근거·사유·실제 완료 시각·해시를 봉인한 후 조건 키를 연결한다. 문체나 내용으로 조건을 추측할 수 있으므로 완전한 눈가림은 아니다. 이번 설계 검토는 진행 AI가 수행했으며 별도 AI의 독립 설계 검토로 표시하지 않는다. [평가자 지침](../experiments/generation_preservation_v1_20260909/reviewer_instructions.md)에 판정 필드를 명시했다.

두 AI의 점수를 각각 보고하고 불일치를 보존한다. 후속 조정이 필요하면 별도 기록을 추가하며 원판정을 덮어쓰지 않는다. 사람 전문가 검증이나 평가 오류의 통계적 독립으로 표현하지 않는다. 기존 v2의 미확정 8건과 새 실험의 미확정은 서로 다른 기록으로 유지한다.

모델이 완료한 요청에서 거절·빈 출력·잘림·schema 오류가 발생하면 전달 상태를 따로 기록하고 파이프라인 과제 완수는 0으로 센다. 의미 평가가 불가능한 응답의 왜곡을 단순히 false로 세지 않는다. 통신 결과 미상이나 중단 이후 미요청 슬롯은 `NOT_OBSERVED`이며, 실패한 실행을 정상 18개 의미 비교로 보고하지 않는다. 계획 18개·시도·완료·평가 가능 수를 모두 공개한다.

전달 실패의 요구사항·왜곡 판정은 문자열 `NOT_ASSESSABLE`로 남겨 의미 미확정 null과 구분한다. 요청한 2~4문장 준수 여부와 인용·메타데이터 정확도는 별도 진단이다. 이 형식 진단이 의미 완수 점수를 단독으로 바꾸지 않으며, schema 오류·빈 설명은 앞의 전달 실패 규칙을 따른다. 모델 snapshot이 다르면 요청 모델 단가로 비용을 확정하지 않고 비용 미확정 상태로 중단한다.

## 실행 통제와 비용

기존과 같은 `gpt-5.4-mini-2026-03-17`, temperature 0, reasoning none, max_output_tokens 900, store false를 쓴다. snapshot과 입력/캐시 입력/출력의 백만 token당 단가 $0.75/$0.075/$4.50은 2026-09-09 [OpenAI 공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.4-mini)에서 재확인했다. 날짜가 달라지거나 API 조건이 바뀌면 실행 전 다시 확인하고 계획 수정 이력을 남긴다.

**개발 실험의 생성 API 비용 한도는 $0.50**, 18회 전체의 보수적 예약 추정은 **$0.1630125**다. 전체 요청의 UTF-8 크기와 schema 크기, 요청당 여유 2,048 및 최대 출력량으로 계산했으며 조건별 금액은 [검증 결과](../experiments/generation_preservation_v1_20260909/validation_report.json)에 기록한다. 캐시 할인은 예약 계산에 쓰지 않는다. 이는 보수적으로 잡은 계획용 추정이며 사업자가 보장하는 청구 상한은 아니다. 실제 반환 usage로 다시 계산하고 Codex 검토 비용과 생성 API 비용을 구분한다. 이번 계획 작성의 생성 API 호출은 0회다.

실행 순서는 고정 seed와 슬롯 ID의 SHA-256 순으로 섞고 순차 요청한다. 매 요청 전 이미 확인된 비용과 다음 요청의 예약액을 더해 한도를 확인한다. 자동 재시도와 성공 응답만 선택하는 재생성은 하지 않는다. 통신 결과 미상, HTTP 오류, usage 누락·이상, 모델 snapshot 불일치는 즉시 중단하고 해당 로그와 미관찰 슬롯을 남긴다. 응답 품질이 낮다는 이유로 반복 수·출력 상한·프롬프트를 실행 중 바꾸지 않는다.

## 결과 집계와 다음 단계의 기준

조건당 동일한 6개 슬롯을 분모로 완수 1/0/null, 미지원·왜곡 true/false/null, 전달 실패를 보고한다. 사례·반복별 전이와 각 요구사항의 변화를 함께 제시한다. 미확정에 대한 `[확인된 완수 수, 확인된 완수+미확정 수]`는 가능한 수의 범위이며 신뢰구간이 아니다. 3개 선정 사례와 2회 반복에서 유의확률·신뢰구간·모집단 성능을 산출하지 않는다.

새 조항 준비로 넘어가는 기준은 **공학적인 보수적 선별 기준**이며 통계적 성공 판정이 아니다. 다음을 모두 만족해야 `READY_FOR_UNSEEN_CLAUSE_PLAN`으로 표시한다.

1. 18개 설명과 두 봉인 평가가 모두 확보되고 원문·요청·usage 검증을 통과한다.
2. 각 검토자에서 A2의 확인된 완수 수가 A0의 확인된 완수+미확정 수보다 크다.
3. 각 검토자에서 A2의 확인된 왜곡+왜곡 미확정 수가 A0의 확인된 왜곡 수보다 많지 않다.
4. 각 검토자에서 A0 완수 1인 대응 슬롯이 A2에서 0/null로 악화되지 않는다.
5. 각 검토자에서 강도 항목(STORAGE_RECOMMENDATION 또는 LOCATION_UNLESS_RECOMMENDATION)의 0→1과 예외 항목(EMERGENCY_EXCEPTION 또는 ECALL_EXCEPTION)의 0→1이 각각 최소 한 번 나타난다.

기준 미달은 `HOLD_FOR_METHOD_REVISION`으로 기록하고 세 조건 결과를 모두 보고한다. A1만 좋아졌다는 이유로 사후에 주 비교나 통과 조건을 바꾸지 않는다. 새로운 방법을 시험하려면 관찰된 결과와 변경 이유를 남긴 별도 버전을 만든다. 일부 항목이 개선됐지만 전체 완수는 그대로인 결과도 유효한 개발 결과다.

## 조건부 2단계: 새 조항에서 재확인

진행 기준을 통과하면 프롬프트와 공통 평가 원칙을 먼저 동결하고, **새 조항 12개 × 같은 3조건 × 2회 = 72회**의 별도 실험을 준비한다. 이는 후속 설계안이며 현재 요청 미리보기나 $0.50 한도에 포함하지 않는다. 12개는 초기 확장 규모로 정한 수이며 통계적 검정력으로 계산한 표본 수가 아니다.

shall/shall not/should/should not/may/can 여섯 층에서 2개씩 고르되 명시적 조건·예외 또는 범위가 있는 능력 명제를 포함한다. 고정된 모델 출력을 보지 않고 후보 목록을 먼저 작성한다. 기존 72건과 모든 개발 사례, 같은 규범 문단이나 문맥 범위를 공유하는 후보, 의미상 중복 조항은 제외하고 그 사유를 남긴다. 공개한 후보 목록 안에서 규격·버전·절·대상 문장으로 정규 ID를 구성한 뒤 고정 seed의 해시 순으로 층별 선택한다.

후보가 부족하거나 source/gold 의미가 불명확하면 생성 전에 HOLD로 두고 수집 계획을 수정한다. 응답을 본 후 쉬운 조항으로 교체하지 않는다. 선택된 조항의 출처·문맥·질문·평가 요구사항을 출력 생성 전에 별도 검토·동결한다. 실제 문맥 길이로 비용을 계산한 후 별도 실행 계획을 확정한다. 지금은 후보 조항, 정답 요구사항, 비용이 확정되지 않았으므로 2단계를 실행할 수 없다.

여기서 미관찰은 **이번 연구의 프롬프트 개발에 사용하지 않았음**을 뜻한다. 모델 사전학습에 없었다거나 3GPP 전체를 대표한다는 뜻은 아니다. 1단계와 2단계 결과를 합산해 단일 성능 수치로 만들지 않는다.

## 준비 상태와 실행 순서

[기계 판독 protocol](../experiments/generation_preservation_v1_20260909/protocol.json), [18개 확정 요청](../experiments/generation_preservation_v1_20260909/request_plan.jsonl), [오프라인 준비·검증 도구](../tools/prepare_generation_preservation_plan_20260909.py), [계획 파일 해시 목록](../experiments/generation_preservation_v1_20260909/plan_review_manifest.json)을 함께 남겼다. 계획 파일 해시 목록은 검토 스냅샷이며, 실행 동결은 별도의 input_freeze_manifest.json으로 검증한다. 최초 초안은 설계 검토 폴더의 draft_snapshot에 보존했다.

새 경로와 18개 슬롯용 [실행기](../experiments/run_generation_preservation_20260909.mjs) 및 [익명 평가 패킷 생성기](../tools/prepare_generation_preservation_review_20260909.py)를 준비했다. 두 도구는 원본 요청·출력·평가 자료의 연결을 검증하며 원본 봉인 뒤에만 실제 평가 패킷을 만든다. 입력 동결 다음은 18회 생성, 원본 봉인, 두 AI 평가 봉인, 조건 연결·집계 순서다. 실행 동결 자체가 API 생성 수행을 뜻하지 않는다. 준비·동결 검증 명령에는 API 호출이나 키 읽기가 없으며 실행기의 execute 명령만 실제 요청을 보낸다.

```bash
python3 tools/prepare_generation_preservation_plan_20260909.py verify
python3 tools/freeze_generation_preservation_20260909.py verify
node experiments/run_generation_preservation_20260909.mjs verify-freeze
```

오프라인 검증은 A0와 과거 FULL/NONE 요청의 정확한 일치, 추가 지시 외 조건 동일성, 평가 정보 제외, 원문 해시와 인용, 18개 슬롯, 반복 입력 동일성, 예산 계산을 확인한다. 실제 의미 보존 효과를 검증한 결과는 아니다. 기존 동결 결과·원고는 보존하고 이번 계획은 별도 후속 개발 기록으로 관리한다.
