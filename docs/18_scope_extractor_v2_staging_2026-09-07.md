# 규범 구절 연결 추출기 v2 준비

2026-09-07. 의미 평가에서 반복된 규범 대상 이동과 조건 누락에 대응하는 v2 프롬프트·출력 스키마·원문 연결 검증기를 구현했다. 현재 상태는 **오프라인 실행 계약 검사 통과**이며 v2 모델 실행·의미 성능 평가·새 조항 검증은 아직 수행하지 않았다. C3 v1이나 C1M의 동결 입력·응답은 바꾸지 않았다.

## 구현된 변경

v1의 여섯 자유 서술 필드만 받는 대신, v2는 원문의 actor_quote, modal_cue, action_quote 및 이 세 부분으로 이루어진 scope_quote를 요구한다. 조건·제한·참조도 원문 그대로의 구절 목록으로 반환하게 한다. 검증기는 다음을 확인한다.

- 추출 입력은 원문뿐이다. 질문, case ID, 기존 응답·점수 및 gold를 넣지 않는다.
- actor·action·scope와 조건·제한·참조 구절이 실제 원문에 존재해야 한다.
- scope_quote가 actor + modal + action과 정확하게 연결되어야 한다.
- 실제 cue와 규범 유형·부정 라벨이 정해진 어휘 대응에 맞아야 한다.
- not all, only, unless, until, without, before, need to, make sure, both, neither, all 및 포착 가능한 백분율·exceed 수치가 핵심 구절 또는 조건·제한에 남아야 한다.
- 단순 see-clause 참조만을 제한으로 분류하면 보류한다. 참조를 예외라는 주장으로 변환하지 않는다.

통과 시 기존 생성 프롬프트용 여섯 필드로 변환할 수 있다. 실패하면 구조를 반환하지 않고 `HOLD` 사유를 남긴다. 통과 상태도 `PASS_EVIDENCE_LINKS_ONLY` / `semantic_status: NOT_EVALUATED`다.

## 오프라인 검증

기존 72개 모든 행에서 원문 이외 필드를 sentinel로 바꿔도 추출 프롬프트가 같음을 확인했다. 합성 fixture로 원문 밖 actor/조건, cue 유형·부정 불일치, 주체와 scope 불일치, unless·98 percent·not all 누락, 참조의 잘못된 역할, 잘못된 스키마를 검사했다. 정상 fixture가 통과하는지도 함께 확인했다.

기계 검사 한계도 의도적으로 테스트했다. 원문의 긴 명사구인 것처럼 잘못 선택한 actor와 scope가 문자 단위로 연결되면 잘못된 문법 분석도 통과할 수 있다. 또한 보호 어구가 남았다는 사실만으로 정확한 의미 결합을 증명하지 못하며, 숫자·양화 표현을 모두 인식하는 검증기도 아니다. 따라서 이 테스트 결과를 추출 의미 정확도로 보고하지 않는다. 원문 밖 congestion처럼 입력 자체에 없는 맥락도 이 버전이 복구했다고 주장하지 않는다.

## 다음 실행 순서

1. C1M의 24시간 지연 재검토로 새 실패·모호성 판정을 조정한다.
2. v2의 API 실행기와 모델·출력 상한·비용 한도·실행 입력을 동결하고 기존 72개에서 개발 비교를 수행한다. v1과 달라지는 스키마·검증기·보류율을 함께 보고한다.
3. 검토 후에 v2를 고정하고 기존 main/pilot과 조항이 겹치지 않는 새 표본을 선정한다. 문장 분할·중복·근접 중복과 원문 문맥을 확인하고, 응답 생성 전에 gold를 동결한다.
4. 새 조항 결과를 확인할 때까지 기존 72개 재평가를 일반화 성능으로 제시하지 않는다. 추가 모델·검색 통합은 이후로 둔다.

관련 파일: `experiments/prompts/c3_scope_extract_v2.md`, `experiments/c3_scope_schema_v2.json`, `experiments/c3_scope_v2.mjs`, `experiments/test_c3_scope_v2.mjs`.

재현: 번들 Node로 `experiments/test_c3_scope_v2.mjs` 실행. 외부 API 호출은 0회다. 이 준비 보고서는 v2 실행 완료를 뜻하지 않는다.
