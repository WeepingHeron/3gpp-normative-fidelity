# 적격성·gold 처리 기준 동결 v1

2026-09-08. 버전 `posthoc_treatment_v1_20260908`. 상태 **`FROZEN_NOT_APPLIED`**.

이번 동결은 72건 적격성 감사 후 사용할 **사후 재평가의 대상·제외 규칙·gold 정정·채점 기준**을 고정한다. 기존 실험 결과를 이미 아는 동일 Codex가 정했으므로 최초 실험의 사전 등록이나 독립 전문가 검증으로 표현하지 않는다. 현재 재채점·성능 집계·새 모델 실행은 시작하지 않았다.

기계 판독 계약은 [protocol.json](../experiments/posthoc_treatment_v1_20260908/protocol.json), 72건별 처리는 [case_policy.json](../experiments/posthoc_treatment_v1_20260908/case_policy.json), 별도 gold 정정은 [gold_overlay.json](../experiments/posthoc_treatment_v1_20260908/gold_overlay.json)에 있다. [동결 채점 기준 v2](../experiments/scoring_v2_frozen_20260908.md)와 [freeze manifest](../experiments/posthoc_treatment_v1_20260908/freeze_manifest.json)를 함께 사용한다.

## 1. 주 분석은 49건, 민감도 분석은 미리 정한 세 집합

일반 적격 50건 중 MAY-001은 잘못된 gold가 C2의 생성 입력에 이미 제공됐다. 채점용 gold를 고쳐도 그 생성 조건을 되돌릴 수 없다. 따라서 **원문 적격성은 유지하면서, 이번 사후 주 분석에서는 모든 조건에서 제외**한다. 이 결정은 특정 모델의 성공 여부에 따른 제외가 아니라 확인된 입력 gold 오염에 따른 것이다.

| 집합 ID | 고정 사례 수 | 구성 | 용도 |
|---|---:|---|---|
| `PRIMARY_STRICT_49` | 49 | 일반 적격 50 − MAY-001 | 이번 사후 검토의 주 분석 |
| `SENS_GOLD_50` | 50 | 일반 적격 50 전부 | MAY-001을 정정 gold로 채점할 때의 민감도 |
| `SENS_EXCEPTION_50` | 50 | 주 분석 49 + SDN-011 | 사전 기록 목록 예외의 민감도 |
| `SENS_GOLD_EXCEPTION_51` | 51 | 일반 적격 50 + SDN-011 | 두 포함 결정이 함께 작용할 때의 민감도 |

같은 50건이라도 두 민감도 집합의 구성은 다르다. 네 집합의 정확한 case ID 배열과 modal·규격·난도별 개수를 계약에 고정했다. 결과가 유리한 집합만 골라 보고하지 않으며, 집합별 분모와 구성이 원래 72건 균형 설계와 달라졌음을 밝힌다. ‘주 분석’은 **이 사후 검토 내부의 우선 분석**을 뜻하며 원래 연구의 확인적 주 분석을 대체하지 않는다.

C0·C1·C2·C3·C1M 모두 같은 집합을 적용한다. 주 비교는 C2−C1, 확장 비교는 C3−C1·C1M−C1·C2−C1M이다. C0는 질문만 받는 기준선으로 별도 기술한다. C2는 계속 oracle structured 조건이며, 정정 후에도 구조화 형식 자체의 인과 효과나 실제 검색 성능을 입증하지 않는다.

## 2. 제외·보류·예외를 고정한다

- **부적격 10건:** 모든 집합에서 제외한다. 원문·응답·기존 판정은 삭제하지 않으며 모델 실패 0으로 변환하지 않는다.
- **보류 11건:** 모든 집합에서 보류한다. CAN-005의 조항 오류가 간단하더라도 이번 버전에서 혼자 복귀시키지 않는다. 문맥 보충·메타데이터 정정·의미 중복·respectively 대응을 해결하려면 근거와 변경 사유를 갖춘 후속 버전이 필요하다.
- **SDN-011:** 사전 예외임을 인정하되 일반 목록 제외 규약을 우선하는 주 분석에서는 제외하고 지정된 민감도에서만 포함한다.
- **SDN-010:** 사전 목록 예외가 있지만 별도의 문맥 문제가 있어 보류를 유지한다. SDN-011과 함께 자동 복귀시키지 않는다.
- **MAY-001:** 원문 적격성을 취소하지 않는다. 입력 gold 오염 때문에 주 분석에서 제외하고 지정된 민감도에서만 같은 정정 기준으로 모든 조건을 검토한다.

판정자가 새로 읽은 PDF 문맥을 과거 모델 입력에 소급 추가하지 않는다. 원문·질문·구조화 필드 중 어느 경로로 제공됐는지 기록하고, 추출기에 없었던 정보를 최종 생성기에 있었다고 해서 추출기의 누락 오류로 처리하지 않는다.

## 3. MAY-001 정정은 원본 수정이 아닌 평가용 overlay

원본 `data/main_cases.csv`와 C2 입력은 그대로 둔다. 새 평가 시에만 다음 두 필드를 별도 overlay로 사용한다.

- `action`: `control both a local UPF and a central UPF` → `have the capability to control both a local and a central UPF within a PDU Session`
- `gold_summary_ko`: 기존 ‘제어할 수 있는 권한이 있을 수 있다’ → **각 SMF가 하나의 PDU Session에서 local UPF와 central UPF를 모두 제어할 수 있는 능력을 갖추는 것은 선택 사항이다.**

actor·condition·modal·polarity 등 나머지 원본 필드는 덮어쓰지 않는다. 능력 보유의 선택성, 능력의 대상, 같은 PDU Session 범위를 보존한다. 모든 SMF의 능력 보유를 확정하거나 제어 권한 부여로 바꾸면 같은 의미로 자동 인정하지 않는다. 정정은 어떤 기존 응답의 PASS/FAIL도 미리 정하지 않는다.

CAN-008의 실제 context 수립 필요조건, SH-005의 `shall be able` 능력 요구, SD-002의 Paging Policy에 걸린 should, CAN-002의 not all 해석은 별도 관계 지침으로 고정한다. 이들은 원본 CSV를 고치는 추가 patch가 아니다. 보류 중인 SDN-002/010과 SD-009의 경계 규칙도 문서화하되 이번 분석 집합에 복귀시키지 않는다.

## 4. 새 v2 평가와 과거 평가를 혼합하지 않는다

v2는 기존 candidate의 R1~R8을 채택하고, 이번 감사의 Non-GBR 범위와 목록 예외·보류·미응답 집계 규칙을 추가했다. `scoring_v2_candidate.md`와 v1은 당시 상태로 보존한다. 평가 대상은 전체 `explanation_ko`이며 JSON 유형·키워드만 맞는 것을 완전 보존으로 인정하지 않는다.

네 집합의 합집합은 51건이다. 후속 적용 단계에서는 **51건 × 5조건 = 255개 응답 슬롯을 모두 같은 v2로 새로 검토**한다. 이번에는 기존 응답을 연결하는 360개 슬롯의 해시 인덱스만 동결했다. 기존 v1/v4 점수를 복사해 v2 값으로 쓰지 않는다. C1M의 이전 기준 지연 pass 2와 새 v2 pass를 합쳐 동일 기준 반복 일치율로 보고하지 않는다.

후속 의미 평가는 조건·기존 점수를 가린 새 순서의 pass 1, 최소 24시간 후 같은 v2의 pass 2, 불일치 조정 순서다. 검토 순서는 `SHA-256(seed|pass|case_id|condition)`의 오름차순으로 고정한다. 표시용 ID에는 조건 이름을 넣지 않는다. 기존 내용을 아는 동일 평가자이므로 조건 표기를 가려도 독립·완전 blind 검증이라고 주장하지 않는다. pass 1 완료 시각·해시 및 실제 24시간 간격을 기록하며 지금 미리 완료했다고 표시하지 않는다.

새로운 source/gold 충돌을 발견하면 근거와 함께 `UNRESOLVED`로 남긴다. 그때마다 불리한 한 조건만 빼거나 과거 지표를 덮어쓰지 않는다. 채점 기준 변경이 필요하면 이 버전을 수정하는 대신 v2 treatment 후속 버전을 만들고 전체 영향 범위를 다시 정한다.

## 5. 미확정과 미생성을 구분하는 집계 계약

설명 의미는 `PASS / FAIL / UNRESOLVED / NOT_SCORED`로 기록한다. 표본 제외·보류와 모델 설명 실패는 다른 축이다.

| 상황 | 의미 상태 | complete_preservation | 집계 처리 |
|---|---|---|---|
| 포함 사례, 충분한 설명, 전부 보존 | PASS | 1 | 해당 고정 집합 분모 유지 |
| 포함 사례, 설명의 명백한 누락·변형 | FAIL | 0 | 같은 분모 유지 |
| 포함 사례, source/gold·응답 해석 미확정 | UNRESOLVED | null | 0/1로 강제하지 않음 |
| 포함 사례, 거절·빈 설명·파싱 실패·생성 보류 | NOT_SCORED | 0 | pipeline 완전 보존 실패로 기록, 의미 오역과 별도 보고 |
| 집합에서 제외 또는 표본 보류 | NOT_SCORED | null | 그 집합 분모에 없음 |

따라서 기존 C3의 생성 보류가 포함 사례에 있으면 분모에서 조용히 제거하지 않는다. 반대로 연구자 측 자료 연결 실패나 해시 불일치는 모델 미생성으로 꾸미지 않고 적용 검증 실패로 처리한다.

미확정 U건이 남으면 N을 유지하고 PASS/N을 **확인된 보존 비율의 하한**, (PASS+U)/N을 상한으로 표시한다. 둘 다 통계적 신뢰구간이 아니라 미확정 판정에 대한 논리적 범위다. U를 0으로 치환한 정확도나 pairwise complete-case 삭제를 금지한다. 해당 비교에 U가 있으면 McNemar와 bootstrap 확정 비교를 보류한다. U=0인 경우에만 기존 방식의 Wilson 95% 구간, exact two-sided McNemar, paired case bootstrap 및 `spec_id + clause_id` cluster bootstrap(각 20,000회, seed 2026090602)을 사용한다. 실제 남은 clause cluster 수를 새로 계산하며 과거 44개를 재사용하지 않는다. 효과 크기는 두 조건의 보존율 차이(%p)로 보고하고, 상대 변화는 기준 비율이 0일 때 정의하지 않는다. 여러 민감도·확장 비교의 p값은 탐색적으로만 해석한다.

## 6. 동결 확인과 다음 단계

검증 명령: `python3 tools/verify_posthoc_treatment_v1.py`.

검증기는 이전 동결 manifest, 새 계약 파일 해시, 72건의 일대일 처리, 네 집합의 정확한 구성과 대칭 적용, MAY-001 patch 전 값, 기존 72×5 응답 슬롯 연결을 검사한다. `--self-test`는 사례 누락·비대칭 집합·보류 복귀·과잉 gold 수정·미확정의 0 변환·응답 해시 변조가 거부되는지 메모리 안에서 확인한다. 원본 파일은 수정하지 않는다.

해시 동결은 변경을 탐지하기 위한 버전 기록이다. 파일시스템 쓰기 금지나 외부 서명을 뜻하지 않는다. README/NEXT_STEPS는 진행 안내이므로 이 연구 계약의 동결 대상에 넣지 않는다. 검증 결과는 별도 receipt로 남기고, 이 문서의 `FROZEN_NOT_APPLIED` 상태는 향후 적용 완료 후에도 당시 이력으로 유지한다.

이번 단계의 완료 조건은 **처리 기준과 적용 대상이 구체적으로 고정되고 검증을 통과하는 것**이다. 다음 단계는 이 동결본으로 v2 검토 패키지를 준비하고 새 평가를 수행하는 작업이다. 모델 재생성·후보 재선정·논문 v5·과거 점수 소급 수정은 이번 동결에 포함되지 않는다.
