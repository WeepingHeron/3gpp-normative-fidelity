# 생성 보존 실험: 제한된 원인 분석

분석일: 2026-09-13. 상태: `BOUNDED_DIAGNOSTIC_COMPLETE_NO_RESCORE`.

**새 조항 실험에 앞서 해결할 문제는 입력 부족보다, 제공된 명제를 한국어 설명에 선택적으로 보존하지 못하는 현상이다.** A2의 공통 실패 4건은 저장 권고 누락 2건과 망의 검증 설정 조건 누락 2건으로 추적된다. 다만 이러한 출력 현상을 일으킨 모델 내부 원인은 이 기록만으로 확정할 수 없다. 진행 상태는 기존 `HOLD_FOR_METHOD_REVISION`을 유지한다.

## 범위와 근거

동결된 3개 개발 원문 × 3조건 × 2회, 총 18개 응답과 두 AI의 기존 판정을 사용했다. 공통 실패 4건과 비교 사례 1건을 실제 요청 → 응답 → 기존 판정까지 연결했다. 실제 요청 문자열에 대상 문장과 제공 문맥의 모든 인용이 포함되는지, 원본 응답과 평가 패킷의 설명이 같은지를 확인했다. 18개 전체의 전달 상태와 출력량도 대조했다. 새로운 생성, 재채점, 평가자 간 조정, 프롬프트 변경은 하지 않았다.

이 분석은 기존 AI 판정에 근거한 사후 진단이며 독립 전문가 검증이 아니다. 앞서 사용한 개발 원문 3개를 다시 살폈으므로 새로운 조항에 대한 성능 근거로 사용할 수 없다.

## 1. 공통 실패가 발생한 위치

| 사례 | 실제 입력에 있던 정보 | 설명에서 관찰한 결과 | 기존 두 평가자의 판정 |
|---|---|---|---|
| GPR-013·016, A2, NSSAI | 대상의 `should be stored`, Annex C의 저장 권고, 별도 문맥의 `can be stored` 모두 제공 | `저장할 수 있으며(can)`를 설명하고 대상의 저장 권고는 누락 | STORAGE_RECOMMENDATION = 0, 전체 완수 = 0 |
| GPR-008·015, A2, AMF | 위치 검증을 통해 PLMN 운용 가능 여부를 확인하도록 망이 설정될 수 있다는 문맥 제공 | 위성 접속·위치정보·ULI는 설명하지만 망의 검증 설정 조건은 누락 | CONFIGURED_VERIFICATION = 0, 전체 완수 = 0 |

NSSAI의 `can`은 모델이 새로 만든 표현이 아니라 실제 제공 문맥에 있다. 따라서 이 문제는 단순한 허구 생성보다 **문맥의 다른 명제를 설명하면서 대상의 권고를 보존하지 못한 것**으로 기술하는 편이 정확하다. 두 평가자 모두 이 두 응답의 미지원·왜곡 주장 여부는 false로 기록했지만, 권고 누락 때문에 완수는 0으로 판정했다. 실제 요청에 권고가 들어 있었으므로 자료 전달 누락으로 설명할 수 없다.

AMF의 망 설정 조건은 A2뿐 아니라 A0·A1을 포함한 해당 원문의 6개 응답 모두에서 두 평가자가 0으로 판정했다. A2만의 새로운 악화라고 볼 수 없다. A2가 위성 접속과 ULI를 포함한 점을 보면 문맥 전체를 무시한 것도 아니다. 관찰 가능한 실패 위치는 필요한 문맥 조건의 선택적 누락이다.

## 2. 가능한 설명과 아직 확정할 수 없는 부분

**질문과 필수 보존 범위의 연결이 약했을 가능성.** AMF 질문은 “필요한 위치정보 조건”을 묻고 망 설정을 직접 열거하지 않는다. 공통 지시에는 필요한 조건을 생략하지 말라는 요구와 무관한 주변 문장 전체를 요약하지 말라는 요구가 함께 있다. 모델이 위치 정확도에 가까운 정보를 우선했을 가능성은 있지만, 이를 인과적으로 검증하지 않았다. 망 설정 조건은 동결된 평가 요구사항이므로 사후에 불필요한 조건으로 제외하지 않는다.

**규범 지시를 명제별 출력으로 연결하지 못했을 가능성.** A1에는 should와 can의 차이 및 `should not A unless B`를 허용의 필요조건으로 바꾸지 말라는 지시가 이미 있다. A2에는 행동·능력 보유·조건·예외를 점검하고 메타데이터만으로 설명을 대체하지 말라는 지시도 있다. “보존 지시가 없었다”는 설명은 맞지 않는다. A2의 내부 점검 과정은 출력하지 않도록 되어 있어, 점검을 수행했는지 또는 어느 단계에서 실패했는지는 관찰할 수 없다.

**짧은 설명 안에서 정보가 경쟁했을 가능성.** 두 평가자의 문장 수 기록은 전부 3문장이다. GPR-016은 저장 권고를 빠뜨리면서 HPLMN/VPLMN 매핑 정보를 담았다. 이는 다른 문맥 정보가 설명에 포함됐다는 증거이며, 그 정보 때문에 권고가 밀려났다는 인과 증거는 아니다. 2~4문장 제한의 영향 역시 별도 비교 없이는 확정할 수 없다.

비교 사례 GPR-017(A1)은 “대상 문장은 이를 ‘should be stored’로 표현하므로 그렇게 저장하는 것이 권고됩니다”라고 can과 should를 함께 보존했다. 하지만 긴급 등록·eCall 삭제 시점은 설명에서 “각각의 삭제 시점”으로 추상화해 두 요구사항 모두 0이었다. 메타데이터에는 deregistration/state/power-off/USIM-removal 등 더 구체적인 삭제 사건 정보가 있다. 이는 정보 일부가 평가 대상 설명 밖에 놓인 사례이며, 메타데이터가 설명 누락을 보충하거나 모델 내부 이해를 증명하지는 않는다.

**강제 잘림이나 전달 실패의 근거는 없다.** 18건 모두 HTTP 200, 응답 상태 completed, incomplete_details = null이었다. 전체 JSON 출력은 212~631토큰으로 제한 900토큰보다 작았다. 이 토큰 수는 설명만의 길이가 아니며, 남은 토큰이 있었다는 사실만으로 짧은 설명 지시의 영향까지 배제할 수는 없다.

## 3. 실제로 진행 기준을 막은 경로

A2 완수는 두 평가자 모두 2/6이다. 그러나 진행 기준은 A2의 완수 수 하나만 보는 규칙이 아니다.

| 동결 기준 | 진행 AI | 별도 AI | 판정 경로 |
|---|---|---|---|
| 실행·봉인·무결성 완료 | 통과 | 통과 | 응답 18건 및 두 평가 봉인 |
| A2 확정 완수 > A0 확정 완수 + 미확정 | 미통과 | 통과 | 진행 AI는 2 > 2가 거짓, 별도 AI는 2 > 1이 참 |
| 왜곡 상한 증가 없음 | 통과 | 통과 | 기존 기준 충족 |
| A0 완수 쌍의 A2 퇴행 없음 | 통과 | 통과 | 기존 기준 충족 |
| 규범 강도와 예외에서 모두 개선 | 미통과 | 통과 | 진행 AI는 규범 강도 0→1 개선을 인정하지 않음 |

진행 AI의 A0 완수 범위는 [1,2], 별도 AI는 [0,1]이다. GPR-004·010의 능력 보유와 구성 허용 해석 차이가 이 범위에 영향을 준다. A2 AMF의 GPR-008·015에서는 “경우에만 … 할 수 있다”와 이어지는 “권고”의 관계를 진행 AI는 왜곡으로, 별도 AI는 보존으로 읽었다. 이 차이가 규범 강도 개선 인정 여부에 영향을 준다. 기존 판정과 미확정을 그대로 유지한다.

따라서 전체 HOLD는 **공통 누락이 남은 상태에서, 두 평가자가 모두 통과해야 하는 기준 중 진행 AI의 두 항목이 미충족한 결과**다. 메타데이터 진단의 정의 혼용은 별도 보조 진단 문제이며 주 진행 기준에 포함되지 않는다. 이를 HOLD의 직접 원인으로 돌리지 않는다.

## 제한된 분석의 종료와 다음 결정

이번 분석은 실패 명제가 실제 입력에 있었는지, 설명의 어디서 빠졌는지, 판정과 진행 기준에 어떻게 연결되는지까지 확인하고 종료한다. 모델 내부 원인을 확정하거나 기존 세 조항이 모두 통과하도록 반복 조정하는 단계로 확장하지 않는다.

다음 방법 수정에서 검증할 핵심은 **대상 규칙의 규범 강도와 문맥 조건을 함께 설명에 남기는가**다. 평가 해석 차이는 별도의 기준 명료화 과제로 다루되 기존 결과에 소급 적용하지 않아야 한다. 정보 선택 방식과 문장 수 제한을 동시에 바꾸면 개선 원인을 구별하기 어려우므로, 후속 실험을 설계한다면 하나의 가설을 선택해 사전 고정하는 것이 적절하다. 새 조항 실험은 그 설계와 진행 기준을 다시 정한 뒤 일반화 확인에 사용한다. 이번에는 후속 프롬프트·조항·실험을 생성하거나 실행하지 않았다.
