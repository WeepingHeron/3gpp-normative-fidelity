# 원문 명제 추출 후 설명 작성: 제한된 개발 실험

2026-09-13 · 실행 전 설계 기록. 실제 동결 시각은 별도 input_freeze_manifest.json을 따른다.

사용자가 선택한 첫 번째 방법을 기존 A2와 비교한다. 질문은 **관찰 가능한 명제 목록을 먼저 생성하면, 최종 한국어 설명의 누락이 줄고 실패 단계가 구분되는가**다. 이미 관찰한 개발 원문 3개만 사용하고 새 조항은 선택하지 않는다. 기존 실험이나 원고는 변경하지 않는다.

## 비교와 고정 사항

| 조건 | 처리 | 최종 설명 수 | API 호출 수 |
|---|---|---:|---:|
| A2_FRESH | 기존 A2의 요청을 그대로 새로 실행 | 6 | 6 |
| P1_EXTRACT_COMPOSE | 원문 명제 자동 추출 1회 → 그 목록을 추가한 A2 설명 1회 | 6 | 12 |

각 조건은 CTX-001·002·003 × 2회다. 과거 결과를 대조군으로 재사용하지 않는다. 동일 반복 번호의 쌍은 분석 편의를 위한 대응이며 API 난수 seed를 공유하지 않는다. 12개 최종 슬롯은 고정 문자열+슬롯 ID의 SHA-256 순으로 실행하고, P1 슬롯은 추출 직후 설명을 실행한다. 추출 결과는 다른 반복에 재사용하지 않는다.

모델 snapshot은 gpt-5.4-mini-2026-03-17, temperature 0, reasoning none, store false다. 최종 설명의 JSON schema·2~4문장·900 출력 토큰 제한·원문·문맥·질문·출처·평가 요구사항은 기존과 같다. 추출 단계는 2,500 출력 토큰으로 제한한다. 명제 목록에는 id, actor, modal, action_or_capability, scope, condition, negation_or_exception, consequent, source_quotes를 기록한다. 이는 관찰 가능한 원문 기반 자료이며 내부 사고 과정을 요구하지 않는다.

추출과 전달은 하나의 방법 변경이지만 **추가 호출·계산량·일반 지시도 함께 늘어나는 묶음 개입**이다. 성능 차이를 구조화 형식만의 효과로 단정하지 않는다. 문장 수 완화나 설명 후 재수정은 추가하지 않는다.

## 정답 유입과 동적 요청 통제

생성기에는 기존 generator_inputs에서 질문·대상 문장·문맥 인용·출처 식별자만 전달한다. 평가 요구사항, 과거 점수, 사례별 정답 힌트는 전달하지 않는다. 평가 필드를 표식으로 바꿔도 요청이 바뀌지 않는 오프라인 검증을 수행한다.

P1 설명 요청은 `기존 A2 입력 + 동결된 공통 suffix + 줄바꿈 + 추출 JSON의 compact 직렬화`로 고정한다. 전체 원문을 계속 제공하고, 자동 추출은 정답이 아니며 충돌 시 원문을 우선하도록 명시한다. 사람이 추출 결과를 수정·보충하거나 일부 명제를 선별하지 않는다. 따라서 추출에는 없는 정보를 최종 설명이 원문에서 회복하는 경우도 관찰할 수 있다.

동적 요청의 실제 바이트는 추출 전에 알 수 없으므로 요청 완성 규칙·schema·소스·실행기·예산을 먼저 동결한다. 실행 시 실제 요청 해시와 선행 추출 응답 ID 및 추출 JSON 해시를 남겨 연결을 검증한다. 최종 설명에는 메타데이터나 추출 목록만의 내용으로 점수를 주지 않는다.

## 비용·실패·보존

[공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.4-mini)를 2026-09-13 확인했다. 백만 토큰당 입력 $0.75, 캐시 입력 $0.075, 출력 $4.50을 사용한다. 기존 키 재사용 승인을 유지한다. 생성 API 한도는 $0.50, 전체 계획 예약 추정은 $0.3212685다. 추출 JSON의 UTF-8 상한 24,000바이트를 후속 입력에 반영하고, 입력·schema 바이트 및 2,048 여유량과 최대 출력량으로 보수적으로 예약했다. 사업자가 보장하는 청구 상한은 아니며 실제 usage로 비용을 다시 계산한다. Codex 분석 비용은 별도다.

응답 quality에 따른 재시도·교체·추출 수정은 없다. HTTP/통신 결과 미상, 모델 불일치, usage 이상, 완료되지 않은 응답, schema 오류, 동적 입력 크기 초과 또는 예산 초과 시 중단하고 12개 슬롯 전체와 18개 계획 호출의 시도·미시도 경계를 보존한다. 잘못된 인용이나 빈 명제 목록은 의미 품질 문제이므로 구조가 유효하면 그대로 후속 단계에 전달한다. 인용 문자열 존재 여부는 보조 진단일 뿐 의미 채점이나 선별 규칙이 아니다. 실행 폴더가 존재하면 재실행을 거부한다.

## 평가 순서와 해석 규칙

1. 최종 설명 12개를 원문·문맥·기존 9개 요구사항과 함께 익명 ID로 제시한다. 조건명·추출 결과를 제외하고 진행 AI가 수동 평가한 뒤 먼저 봉인한다. 진행 AI는 설계를 이미 알므로 완전한 눈가림이나 독립 평가라고 부르지 않는다.
2. 기존과 동일하게 요구사항은 1/0/null, 미지원·왜곡 주장은 true/false/null이다. 명확한 요구사항 0 또는 왜곡 true이면 완수 0, 그 외 미확정이 있으면 null, 나머지는 1이다. 인용·문장 수·메타 진단은 별도다.
3. 기존 논점인 능력 보유와 행동 허용, should not unless와 강한 필요조건의 차이는 문장 전체로 판정한다. 해석이 갈리는 표현을 키워드만으로 통과시키지 않고, 해결되지 않으면 null과 두 해석을 남긴다. 망 설정 조건과 구체적인 삭제 사건은 기존 요구사항 그대로 유지한다. 기존 결과는 재채점하지 않는다.
4. 최종 평가를 봉인한 뒤 추출 6개를 별도 진단한다. 명제의 구조화 필드가 요구사항을 보존해야 하며 source_quotes에 원문이 복사된 것만으로 추출 성공을 인정하지 않는다. 실제 필드 및 원문 근거를 남긴다.
5. 추출/설명의 요구사항 쌍은 0/0=추출부터 누락, 1/0=설명 단계 소실, 0/1=설명에서 회복, 1/1=보존, null 포함=미확정으로 보고한다. 0에는 오류도 포함되므로 세부 사유로 누락과 왜곡을 구분한다. 단계 연결은 관찰 결과이며 인과 실험으로 모델 내부 원인을 확정하지 않는다.

이번 제한된 실행에서는 진행 AI의 1차 검토와 단계 진단까지 수행한다. 별도 평가자가 이미 검토했다고 표시하지 않는다. 향후 독립 검토용 최종 패킷을 남기고, 기존 두 평가자 진행 기준을 한 평가자 결과로 대체하지 않는다.

## 사전 고정한 결과 해석과 종료

새 A2와 P1의 완수 1/0/null, 왜곡 true/false/null, 대응 쌍·항목별 변화, 추출→설명 소실을 모두 보고한다. P1 확정 완수가 A2 완수 상한보다 크고, A2 완수 쌍의 퇴행이 없으며, P1 왜곡 상한이 A2 확정 왜곡보다 크지 않을 때만 **1차 개선 후보**라고 부른다. 이 기준을 충족해도 단독으로 새 조항 진행 승인을 내리지 않는다. 나머지는 개선 미확정으로 기록한다. 과거 실험의 HOLD는 이 실험으로 덮어쓰지 않는다.

3개 개발 원문의 결과를 모집단 성능이나 통계적 유의성으로 보고하지 않는다. 실패해도 실행 중 프롬프트·출력 상한·반복 수를 바꾸지 않는다. 이번 18회와 1차 진단을 마치면 종료하고, 별도 방법 변형이나 새 조항 실험으로 자동 확대하지 않는다.
