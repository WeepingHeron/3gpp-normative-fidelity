2026-09-09. **별도 AI의 기존 응답 검토 15건과 후속 생성 실험 24건·두 AI 평가를 완료했다. 문맥을 추가하면 일부 조건 정보가 더 잘 남았지만, 지정한 전체 과제의 완수 향상은 확인되지 않았다.** 상태는 `SEPARATE_AI_REVIEW_AND_MICROSTUDY_COMPLETE`다. 개발 실험의 보조 근거로 공유할 수 있으며 성능 향상이나 일반화의 입증으로 반영하지 않는다.

## 기존 응답의 별도 AI 검토

이전 대화를 전달하지 않은 새 AI 문맥에서 세 원문×전체 다섯 조건의 응답 15개를 검토했다. 검토자는 동결 v2, 원문·질문·응답과 판정자 전용 PDF 페이지를 읽었고 기존 판정·조건 키·결과 보고서는 읽지 않았다. 판정을 실제 시간·인용·파일 해시와 함께 봉인한 뒤 기존 조정 판정과 대조했다.

결과는 PASS 1·FAIL 6·UNRESOLVED 8로 **15건 모두 기존 판정과 일치**했다. 따라서 기존 v2 점수와 주 분석 49건·민감도 50/50/51건의 범위를 변경하지 않는다. 별도 AI 문맥의 일치이며 사람 전문가 검증, 오류의 통계적 독립, 무작위 표본의 평가자 신뢰도 추정으로 해석하지 않는다. 검토 안내와 원문 제공 여부에서 실험 조건을 추론할 수 있어 완전한 눈가림도 아니다.

## 후속 실험의 질문과 범위

새 실험은 기존 미확정을 점수 변경으로 해소하기 위한 재생성이 아니다. **문맥 정보와 사례별 규범 힌트를 제공했을 때, 지정한 문맥 포함 설명 과제를 얼마나 완수하는지** 살펴보는 개발 실험이다. 관찰된 어려움을 바탕으로 고른 세 원문이므로 미관찰 조항의 일반화 성능으로 보고하지 않는다.

| 사례 | 대상 | 문맥과 질문의 범위 |
|---|---|---|
| CTX-001 | SMF의 선택적 능력 보유 | 직전의 복수 PDU Session 문단. 핵심 명제는 짧은 원문에도 있는 대조 사례다. |
| CTX-002 | allowed NSSAI 저장·사용·삭제 | 비-SNPN 모드의 Annex C.1 중 저장 권고, SUPI 사용 조건, 긴급 등록/eCall 예외. 해당 범위를 질문에도 명시했다. |
| CTX-003 | AMF의 위치정보와 비권고 | NR 위성 접속의 절 범위와 위치 검증 설정 문맥. |

CTX-002는 기존 질문보다 범위를 구체화했다. Annex C 전체의 모든 명제나 SNPN 모드까지 평가하지 않으며, 완전성은 고정한 요구사항 집합에 대한 완전성이다. 제공한 주변 문맥에서 요구사항으로 지정하지 않은 부수 명제를 전부 나열하게 요구하지 않는다. 원문을 분명히 왜곡하는 추가 주장은 별도로 평가한다.

## 실행 전에 고정한 비교

세 원문×짧은 원문(SHORT)/문맥 포함(FULL)×사례별 힌트 없음(NONE)/규범 유형·극성 힌트(MODAL)×2회 반복으로 24개 슬롯이다. 두 반복의 입력은 같으며 서로 독립적인 새 원문으로 세지 않는다. C2 gold 구조나 C3 자동 추출 변경은 이번 비교에 포함하지 않는다.

모델은 기존 연구와 같은 `gpt-5.4-mini-2026-03-17`, temperature 0, reasoning none, 출력 상한 900 token, store false다. 공통 지시는 2~4문장의 한국어 설명과 JSON 메타데이터를 요구한다. 두 힌트 조건 모두 일반적인 규범 구분 안내를 받으므로 MODAL 효과는 **사례별 라벨 추가의 효과**다. FULL은 같은 대상·질문·힌트·출력 상한에서 인용 문맥만 추가한다. 일부 문맥에는 대상 문장도 반복되므로 정보 추가와 길이·반복 효과를 완전히 분리하는 설계는 아니다.

모델 snapshot과 token 단가는 [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.4-mini)에서 확인했다. 표준 입력/캐시 입력/출력 단가는 백만 token당 각각 $0.75/$0.075/$4.50을 비용 추정에 사용한다. 24건의 보수적 비용 예약 추정은 $0.188856, 실행 상한은 $0.50이다. 비용은 실제 반환 usage로 재계산하는 추정이며 청구서가 아니다. 자동 재시도는 하지 않는다.

## 실행 전 검토에서 보완한 기준

별도 AI가 원문과 실험 설계를 검토하면서 단일 JSON 유형 필드가 여러 문맥 규범을 어떻게 표현하는지와 판정 면을 명시할 필요를 지적했다. 실행 전에 메타데이터는 대상 문장을 분류하고, 의미 평가는 `explanation_ko`만 사용하도록 명확히 했다. JSON 필드의 올바른 라벨이 설명의 오류를 고치지 않으며, 메타데이터 오류만으로 설명 점수를 바꾸지도 않는다. 필드 간 모순은 별도로 기록한다.

요구사항의 여러 조건과 삭제 계기가 모두 보존돼야 해당 항목을 1로 본다. 누락·명시적 모순은 0, 의미가 결정되지 않으면 null이다. 문체나 특정 번역어 일치는 요구하지 않는다. [실행 전 source/design 검토](../outputs/review/context_microstudy_preflight_20260909/review.md).

## 두 결과 축

**문맥 포함 과제 완수**는 모든 조건에서 동일한 요구사항 집합을 사용한다. 문맥이 없는 SHORT도 분모에 남고 해당 정보가 빠지면 과제 완수는 0이다. 그러나 그 누락은 `INPUT_CONTEXT_GAP`으로 구분하며 곧바로 오역으로 세지 않는다. 제공되지 않은 정보를 모른다고 정직하게 밝힌 응답도 불완전하지만 충실할 수 있다.

**근거 없는 주장·왜곡**은 실제 제공된 대상·질문·문맥을 기준으로 별도 평가한다. 답변의 세부 정보가 제공된 근거에 없으면 과거 지식으로 맞을 수 있더라도 이 source-only 과제에서는 미지원 주장일 수 있다. 입력에 없던 조건의 단순 생략과 명시적 잘못된 일반화를 구분한다.

두 AI가 서로의 판정과 조건별 결과를 보기 전에 모든 응답을 각각 검토한다. 항목별 인용과 사유를 봉인한 뒤 대조한다. 미확정을 억지로 0/1로 바꾸지 않고, 불일치가 남으면 두 판정 또는 별도의 조정 근거를 보고한다. 어떤 통계 검정이나 신뢰구간도 이 3개 선정 사례·2회 반복에서 산출하지 않는다.

## 실행·평가 결과

입력 동결은 2026-09-09 **15:11:26.953 KST**, 실제 API 실행은 **15:11:53.045–15:12:59.978 KST**였다. 24회 요청 모두 HTTP 200으로 완료됐고 24개 설명을 파싱했다. 재시도·재생성·출력 잘림은 없었다. 반환 usage를 공식 단가로 계산한 **생성 API 비용 추정은 $0.0445545**다. 별도 Codex 검토의 계정 사용량이나 전체 연구 비용을 포함하는 금액은 아니다.

진행 AI는 15:18:31 KST에 24건의 수동 판정을 봉인했고, 별도 AI는 15:25:14 KST에 검토 manifest를 확정했다. 이후 조건 키와 연결했다. 두 AI가 같은 24개를 평가한 것이므로 평가 레코드 48개를 생성 표본 48개로 세지 않는다.

아래 표의 **전체 완수·미완수·미확정과 미지원/왜곡 여부는 두 AI가 모두 동일하게 판정**했다. 각 행의 분모는 3개 원문×2회 반복인 6개 슬롯이다.

| 입력 | 사례별 힌트 | 전체 완수 | 미완수 | 미확정 | 미지원·왜곡 확인 | 미지원·왜곡 미확정 |
|---|---|---:|---:|---:|---:|---:|
| SHORT | NONE | 2/6 | 4/6 | 0/6 | 4/6 | 0/6 |
| SHORT | MODAL | 2/6 | 4/6 | 0/6 | 2/6 | 0/6 |
| FULL | NONE | 2/6 | 4/6 | 0/6 | 4/6 | 0/6 |
| FULL | MODAL | 1/6 | 4/6 | 1/6 | 3/6 | 1/6 |

두 힌트 수준 모두 문맥 추가 후 확인된 전체 완수 수가 늘지 않았다. FULL+MODAL은 1건 미확정을 성공으로 가정해도 2/6으로 같은 힌트의 SHORT와 같다. 이는 이 선정 사례의 기술적 결과이며 문맥이 해롭다는 인과 주장이나 다른 사례에서도 향상이 없다는 주장은 아니다. 합계는 두 검토자 모두 **완수 7·미완수 16·미확정 1**, 미지원/왜곡은 **확인 13·없음 10·미확정 1**이다.

전체 완수가 늘지 않았다고 해서 추가 문맥을 전혀 사용하지 않은 것은 아니다. 아래는 두 힌트와 두 반복을 합친 **같은 원문당 4개 슬롯**의 세부 요구사항 결과이며 두 AI가 일치했다.

| 원문·세부 요구사항 | SHORT에서 보존 | FULL에서 보존 | 해석 |
|---|---:|---:|---|
| CTX-002 SUPI 결합·일치 시 사용·불일치 삭제 | 0/4 | 4/4 | 해당 문맥을 제공하면 이 정보는 네 설명 모두에 나타났다. |
| CTX-002 기본 저장 권고 강도 | 2/4 | 1/4 | FULL에서도 저장 should를 의무로 바꾸는 오류가 남았다. |
| CTX-002 긴급 등록의 저장·삭제 예외 전체 | 0/4 | 0/4 | FULL 네 설명 모두 긴급 서비스 등록 해제 시 삭제를 누락했다. |
| CTX-003 NR 위성 접속 범위 | 0/4 | 2/4 | 추가 문맥의 상위 범위가 일부 설명에 반영됐다. |

SHORT의 미제공 SUPI·위성 접속 정보 생략은 입력 문맥 부족으로 구분했다. 반면 should/should not은 짧은 원문에도 있었으므로 강도 강화는 입력 부족만으로 설명할 수 없다. FULL의 긴급 삭제 조건은 실제 입력에 있었으므로 응답에서 빠진 누락이다. 이 구별이 이번 실험에서 얻은 핵심 개발 근거다.

예를 들어 MCR-011은 저장을 “권고”한다고 정확히 구분하고 SUPI 일치·불일치 처리도 설명했다. 그러나 긴급 등록 시 임시 저장 다음에 eCall 삭제 계기로 넘어가 긴급 서비스 **등록 해제 시 삭제**가 빠졌다. 메타데이터에 더 많은 예외 정보가 있어도 한국어 설명의 누락을 복구하지 않았다. MCR-007/015는 NR satellite access를 언급했지만 “해서는 안 됩니다”라는 강제 금지를 사용해 대상의 비권고를 보존하지 못했다.

## 검증과 공유 수준

판정 후 새로 합의한 성공 기준이나 제외 사례는 없다. 실제 요청 24건을 실행 전 계획과 일대일 대조하고, 원본 response의 모델 snapshot·출력 JSON·usage를 다시 확인했다. 두 검토의 입력/출력 해시, 24개 고유 ID, 항목별 인용·값 타입·전체 완수 계산, 조건별 동일 분모를 확인했다. Python 집계와 독립 SQLite 쿼리가 8개 검토자별 조건 집계에서 일치했다. 기존 v2와 원본 응답의 봉인 검증도 유지됐다.

공유 수준은 **Share with caveats**다. 새로운 평가자 불일치 두 건은 원본 판정과 함께 공개했으며, 주요 두 결과 축에는 차이가 없다. 검증 코드는 명제의 진실성이나 전문가 타당도를 자동 증명하지 않는다. 선정된 세 원문, 같은 모델 계열의 두 AI, 반복·입력 길이·대상 문장 반복, 제한된 출력 길이, 새로운 prompt 및 CTX-002 질문 변경을 함께 밝혀야 한다. 이 기록은 사후에 시작한 후속 실험이며 전체 연구를 사전 등록한 것으로 표시하지 않는다.

## 반영 범위

기존 v2 결과는 [현재 조건별 보고](28_v2_cohort_results_2026-09-09.md)를 유지한다. 새 실험은 prompt·문맥·CTX-002 질문·평가 대상이 달라 기존 보존율과 합산하거나 이전 255개 응답의 점수를 대체할 수 없다. 이번 결과는 **문맥 정보 확보와 규범 강도·예외 관계 보존을 분리해야 한다는 개발 근거**와 오류 사례로 반영할 수준이다. 성능 향상 주장의 근거로 사용하지 않는다. 주 성능 주장을 넓히려면 이후 개선안을 별도 버전으로 동결하고 새 조항에서 검증해야 한다. 이번 작업에서는 원고를 갱신하거나 추가 모델 실행을 이어가지 않았다.
