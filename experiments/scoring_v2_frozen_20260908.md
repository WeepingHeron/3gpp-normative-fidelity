# 의미 평가 기준 v2 동결본: 규범 적용 범위와 근거 출처

상태: `FROZEN_NOT_APPLIED`. 2026-09-08 동결. 2026-09-07 후보를 기반으로 별도 버전에 채택했다. 기존 응답과 결과를 본 뒤 만든 후속 평가 기준이다. 사전 등록된 기준, 독립 전문가 합의, 기존 점수의 확정 정정으로 표시하지 않는다. `scoring_v1.md`, main gold, 생성 입력·응답, 기존 평가 점수는 보존한다.

## 1. 판정 순서

1. **표본 적격성**: source의 원래 문서 영역과 선정 규약을 확인한다. 문장에 NOTE라는 문자열이 없다는 이유로 NOTE 영역에서 나온 문장을 채택하지 않는다. 사전 제외 범주에 속하면 `INELIGIBLE_UNDER_ORIGINAL_PROTOCOL`로 기록한다. 모델 설명 실패와 별개의 상태다.
2. **기준 타당성**: gold의 각 명제가 원문 또는 명시적으로 제공된 문맥에 연결되는지 확인한다. gold와 원문이 충돌하면 gold를 따르는 답을 자동 성공 처리하지 않는다. 수정안은 별도 errata로 남긴다.
3. **명제와 연결 관계**: 규범 표현이 어느 행위자·행동에 걸리는지, 조건이 필요조건인지, 한정이 어느 집합에 걸리는지 분해한다.
4. **설명 전체의 의미**: 모든 필수 명제가 보존되고 미지원 주장이 없는지 판단한다. JSON 유형 일치는 이 판단을 대신하지 않는다.
5. **상태와 근거 기록**: 아래 의미 상태 및 불확실성 사유를 기록한다. 불명확한 상태를 0 또는 1로 몰래 변환하지 않는다.

## 2. 판정 단위와 원문 출처

`actor/modal/action` 한 묶음이 모든 문장을 표현한다고 가정하지 않는다. 규범 요소를 다음처럼 명제별로 기록한다. 기계 추출기 구현 또는 새 schema의 배포를 의미하지 않는 수동 판정용 표현이다.

- `actor`: 해당 명제의 의미상 주체. 수동태의 문법적 주어만으로 고정하지 않는다.
- `modal_surface`: 원문에 나타난 표현. `can` 하나가 있다는 사실과 문장 전체가 능력만을 말한다는 해석을 구분한다.
- `modal_scope`: 규범 표현이 직접 적용되는 구절.
- `action_or_state`: 행동뿐 아니라 능력 보유와 같은 상태를 허용한다.
- `condition`, `quantifier`, `limitation`: 조건, 수치·집합 한정, 예외·범위를 구분한다.
- `relation`: 필요조건, 시간적 선행, 선택지, 중첩된 능력 보유 등 명제 간 관계.
- `provenance`: `supplied_source`, `supplied_question_context`, `adjudication_only_context` 중 어디에 있는지와 규격·버전·PDF 페이지를 기록한다.
- `available_to_extractor` / `available_to_generator`: 실제 요청에 해당 근거가 있었는지 별도로 표시한다.

질문의 전제도 무조건 사실로 채택하지 않는다. 규격 문맥과 일치하는지 확인한다. 판정자가 PDF에서 새로 확인한 문맥은 원래 모델 입력에 소급 추가하지 않는다. 자동 추출 입력에 없는 조건은 `INPUT_CONTEXT_GAP`으로 기록하며 단순한 추출 의미 오류와 분리한다.

## 3. 적용 범위 규칙

### R1. 능력 보유와 행동 허용

`may have the capability to X`는 `may [have the capability to X]`의 범위를 보존한다. `may [X]`로 바꾸거나 모든 주체가 이미 X 능력을 보유한다고 확정하면 같은 의미라고 자동 인정하지 않는다. capability를 한국어 ‘권한’으로 바꾸지 않는다. 보유 여부의 선택성과 능력의 대상 X를 함께 남긴다.

### R2. 필요조건과 능력

`Before S can be activated, A and B need to establish C`에는 S 활성화 가능성과 A/B의 실제 C 수립 전제가 함께 있다. ‘C를 수립할 능력만 있으면 S 활성화가 가능하다’는 실패다. ‘C 수립 능력이 필요하다’만 쓰면 실제 수립 조건이 빠져 실패다. C 수립을 S 활성화의 충분조건으로 뒤집어서도 안 된다.

### R3. 설명 전체와 보충 문장

두 문장은 함께 읽는다. 첫 문장의 약한 진술이 원문의 함의이고, 둘째 문장이 빠진 필수 조건을 명확히 복원한다면 첫 문장이 약하다는 이유만으로 실패 처리하지 않는다. 실제 수립이 필요하다고 명시한 설명에 수립 능력이 필요하다는 부연이 있다고 해서 자동 실패시키지 않는다.

반면 ‘능력만 있으면 충분하다’와 ‘실제 수립이 필요하다’처럼 실질적으로 충돌하는 주장이 함께 있으면 실패다. 뒤에 맞는 단어가 나왔다는 이유만으로 앞의 오류가 사라지지 않는다. 명시적 정정이 있는 경우 독자가 따라야 하는 최종 명제가 단일하고 분명한지 판단하고, 그 판단 근거를 기록한다. 지시 대상이 불명확하면 `UNRESOLVED`로 남긴다.

### R4. 규범 표현과 주체·행동 연결

유형 이름이 맞아도 규범이 다른 행동에 걸리면 실패다. `which Paging Policy should be applied`의 should를 애플리케이션의 DSCP 설정 권고로 옮기지 않는다. 단순한 능동·수동 전환은 의미 관계가 같으면 허용한다. 포함된 보조 명제와 주된 규범 명제를 모두 보존한다.

### R5. 양화와 파생 설명

`98 percent ... should not exceed PDB`에서는 비혼잡 조건, 98%, PDB 초과 지연의 비권고를 보존한다. 같은 모집단과 권고 강도를 유지한 2% 보완 표현은 허용한다. 2%를 반드시 별도로 언급하게 요구하지 않는다. ‘정확히 2%가 초과한다’, ‘나머지 2%의 초과를 규격이 허용한다’, 측정된 성능이나 하드 보장을 뜻하는 표현은 인정하지 않는다.

`Not all events can ...`은 전부가 가능하다는 주장으로 바꾸면 실패다. 다만 그 문장만으로 성공 가능한 event가 반드시 하나 이상 존재한다고 보장하지 않는다. 가능 집합을 정확히 특정하는 추가 주장에는 별도 근거가 필요하다.

### R6. 모호한 respectively와 선택지

원문이 PLMN identity, SNPN identity, SNPN list를 언급하지만 대응 관계가 확정되지 않으면 존재하는 선택지와 관계의 불확실성을 분리한다. 원문에 없는 일대일 대응을 만들어내지 않는다. 전후 문맥으로도 해결되지 않는 대응 관계를 단일 gold로 고정해 특정 표현만 정답으로 삼지 않는다.

명백한 요소 누락과 가능한 문법적 해석의 차이를 구분한다. 후자만으로 성공/실패가 갈리면 `UNRESOLVED_SOURCE_MAPPING`을 기록한다. 모호한 부분 외에 별도의 명백한 오류가 있으면 그 오류에 근거한 실패는 가능하다.

### R7. 참조·설명·예외

`see clause ...`와 같은 출처 안내만으로 동작의 예외나 적용 조건을 새로 만들지 않는다. 다만 실제 참조 대상이 규범 조건을 담는다면, 그 조건의 문서 출처 및 모델 제공 여부를 구분한다. gold exception 칸에 들어 있었다는 사실 자체가 예외의 정당화가 되지 않는다.

### R8. 전문 용어

전문 용어는 원어 유지 또는 의미가 맞는 한국어 표현을 모두 허용한다. `mobile terminated`를 착신 서비스와 다른 대상으로 바꾸는 오역은 행동 대상 보존 실패다. 용어를 영어로 남겼다는 이유로 감점하지 않고, 문체·자연스러운 어순만으로도 감점하지 않는다.

## 4. 상태와 집계 원칙

| 축 | 값 | 의미 |
|---|---|---|
| eligibility | `ELIGIBLE`, `INELIGIBLE_UNDER_ORIGINAL_PROTOCOL`, `REVIEW_REQUIRED` | 표본 적격성. 모델 점수가 아님 |
| gold status | `SOURCE_SUPPORTED`, `CORRECTION_PROPOSED`, `UNRESOLVED` | 기준 명제의 근거 상태 |
| semantic judgment | `PASS`, `FAIL`, `UNRESOLVED`, `NOT_SCORED` | 설명 전체의 의미 판정 |

기존 이진 점수와 새 검토 상태를 같은 열에 저장하지 않는다. 새 점수를 보고하려면 동일 기준을 영향받는 모든 조건에 적용하고, 기준 변경 전후 및 판정자 정보를 공개한다. 모호한 사례를 한 조건에서만 제외하지 않는다. 적격성 제외와 의미 실패를 혼합하지 않는다.

기존 72건과 그 집계는 이력으로 보존한다. 사후 적격성 제외 분석은 별도 분모·목록·사유를 보고하며, 원래 72건의 균형 표본과 같은 설계라고 주장하지 않는다. 제외한 자리에 새 문장을 채워 기존 실행과 섞지 않는다. 새 표본·새 prompt 실험은 별도 버전으로 동결한다.

이 기준을 적용할 때까지 v4 수치는 기존 기준의 잠정 연구 기록으로 읽는다. 본 문서 작성 자체는 72건 재평가나 C1M 지연 pass 2의 완료가 아니다. 반복 검토 일치율은 전문가 정답 타당도의 대용 지표가 아니다.

## 6. 2026-09-08 처리 계약에 따른 운영 규칙

이 동결본은 `posthoc_treatment_v1_20260908`에만 적용한다. 원래 candidate와 scoring_v1은 변경하지 않는다. 데이터 적격성의 세부 상태와 집계는 `docs/22_posthoc_treatment_freeze_2026-09-08.md` 및 동봉 protocol.json이 구체화하며, 위의 일반 원칙과 운영상 차이가 있으면 이 절의 명시적 규칙을 따른다.

- 일반 적격 50건에서 MAY-001을 뺀 49건을 사후 주 분석으로 삼는다. 지정된 세 민감도 집합은 각각 50·50·51건이다. 부적격 10건·보류 11건은 어느 집합에도 복귀하지 않는다.
- MAY-001은 동봉 gold_overlay만 새 채점에 사용한다. 잘못된 C2 생성 입력이 교정됐다고 간주하지 않는다. 원본 source·question·gold·response는 그대로 둔다.
- SH-005의 shall be able은 허가된 데이터 변경 능력의 요구이다. 모든 CRUD 동작을 실제로 수행하라는 요구로 바꾸지 않는다.
- R5의 98% 판단에서는 Non-GBR 범위가 앞 문맥에 있다는 사실을 기록한다. SDN-002는 이번 버전에서 HOLD이며, R5 예시가 그 사례를 자동 포함시키지 않는다.
- 판정자 전용 PDF 문맥과 실제 제공 source/question의 provenance를 구분한다. 새로운 미확정 gold를 발견하면 UNRESOLVED로 기록하고 사례 집합을 조건별로 달리 바꾸지 않는다.
- 합집합 51건×C0/C1/C2/C3/C1M을 같은 v2로 새로 검토한다. 기존 점수 복사·특정 실패 행만 수정·v1 평가와 v2 평가의 혼합은 금지한다.
- 포함 사례의 설명을 판단할 수 없으면 UNRESOLVED와 complete_preservation=null이다. 포함 사례의 거절·빈 응답·파싱 실패·생성 보류는 semantic=NOT_SCORED와 complete_preservation=0으로 기록하여 pipeline 실패와 의미 오역을 구분한다. 제외/표본 보류 행은 NOT_SCORED와 null이며 해당 집합 분모 밖이다.
- 자료 누락·해시 불일치는 연구 적용 검증 실패다. 모델의 미생성으로 바꾸지 않는다. 미확정이 남으면 확인된 PASS/N과 (PASS+U)/N 범위 및 U를 함께 보고하고 해당 비교의 확정 통계 검정을 보류한다.
- 설명 전체의 필요조건·논리적 함의·명시적 상충·관계·양화·용어 의미를 검토한다. 이전 응답에 대한 특정 성공/실패 결론을 규칙에서 미리 정하지 않는다.
- 미래 기록은 treatment/rubric 버전·응답 record hash·review pass·시간·semantic/delivery 상태·gold 상태·판정 근거와 provenance를 포함해야 한다.

이 버전 동결 시점의 적용 건수는 0이다. 새 점수와 검토 산출물은 별도 출력 경로에 저장하고 이후에도 이 파일을 수정하지 않는다.
